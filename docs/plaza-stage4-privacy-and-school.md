# 광장 4단계 — 기록 선택·학교 제출·책임 검토안

작성일: 2026-10-04. 기준: `plaza-plan.md`, `plaza-design.md`의 D8·D9·D10.

이 문서는 학교와 검토할 구체적인 처리 흐름이다. 학교별 계약·처리 근거·기간을 승인한 문서가 아니다. 구현은 별도 로컬 시험 DB와 가짜 참여자만 대상으로 한다. `real_collection_allowed`는 항상 `false`이며 운영 활성화 스위치는 없다.

## 1. 학생의 선택과 수업 참여

| 선택 | 서버 동작 | 수업 활동 |
|---|---|---|
| 진로기록 남기기 | 입장 때 진로기록 학생 UUID와 게스트 연결 생성. 마지막에 본인이 확인하고 저장할 때 원본 INSERT | 구상·제작 확인·교류·돌아보기 |
| 진로기록 없이 활동하기 | 광장 참여자만 생성. `career_log.students`, `job_identities`, `records`, 최종 접수 사본 생성 안 함 | 동일한 활동 후 별도 ‘활동 완료’ 처리 |
| 작품 사진 전시 허용 | 담당 강사가 작품만 촬영하고 이번 수업 안에서 전시 | 장기 진로기록 선택과 독립 |
| 사진 없이 참여하기 | 촬영 예약·전송·사진 옮기기 서버 거절. 구상 전시 유지 | 방문 배정과 활동 완료에 영향 없음 |

입장 화면의 기록·사진 라디오 버튼에는 기본 선택이 없다. 시험 안내 버전과 선택값을 함께 보낸다. 기기 교체·입장 응답 유실에도 같은 참여자와 선택을 유지한다. 비기록 입장 시 이전 사람의 진로기록 접근·이어가기 쿠키를 만료시키며, 일반 `/api/career-log/start` 우회도 막는다.

‘기록 없이’는 개인정보를 전혀 처리하지 않는다는 뜻이 아니다. 기존 수업 코드 로그인, 접속, 자리와 가게, 구상·교류·성찰은 수업 진행에 필요한 임시 처리다. 임시 처리 자체에 대한 학교의 근거와 안내가 없으면 실제 학생에게 이 경로도 열지 않는다. 이름·전화번호·학교명·얼굴을 작품명, 소개, 성찰에 적거나 촬영하지 않도록 안내한다. 법적 동의가 필요한 처리를 단말의 선택 버튼만으로 충족했다고 보지 않는다.

이번 기록 선택은 입장 시 정하며, 이미 생성한 장기 원본을 화면에서 ‘철회 완료’로 바꾸지 않는다. 기록 선택을 잘못했거나 장기 기록의 정정·삭제를 요구하면 학교의 담당자에게 접수한다. 원본은 기존 append-only 체계를 유지하고 승인된 기존 시스템 절차가 마련될 때까지 삭제 완료라고 회신하지 않는다. 사진은 활동 도중과 활동 완료 후에도 학생이 중지·삭제 요청할 수 있다. 새 사진 허용으로 되돌리는 기능은 없다.

## 2. 자료별 보관·파기 결정표

학교·모아킷 담당자가 아래 미정 항목을 확정하고 승인 문서 번호·담당자·일자를 남겨야 한다. 시험의 0~87600시간 입력 범위는 소프트웨어 검증 범위이고 법정 보관 기간이 아니다. 운영 기본값을 임의로 정하지 않았다.

| 자료 | 목적·접근 | 이번 구현의 파기 | 운영 결정 상태 |
|---|---|---|---|
| 작품 현재본·재촬영 이전본·예약된 임시 파일 | 수업 내 작품 전시, 본인·담당 강사·해당 수업 참여자 | 사진 기한 도래 또는 본인의 사진 철회. 파일 삭제 후 실제 부재 확인 | 사진·임시본 기간 미정 |
| 초안·제작 확인·AI 출처·교류·돌아보기·최종 접수 사본 | 활동 진행, 본인 또는 교류 당사자 | 활동 기한에 광장 표 원문 삭제. 원본 진로기록과 분리 | 활동 기간 미정 |
| 광장 접속·재발급·배정 변경·운영 이력·참여자 연결 | 수업 권한과 장애 복구 | 사진과 활동 파기 이후 운영 기한에 삭제 | 운영 이력 기간 미정 |
| 진로기록 학생 UUID·연결·`career_log.records` | 선택한 장기 기록과 기존 열람 | 광장 파기로 UPDATE/DELETE하지 않음. 별도 시스템 절차 필요 | **원본 파기 절차 미해결** |
| 기존 게스트 계정·공통 접속 기록 | 기존 aiapp 로그인·감사 | 기존 관리 영역. 만료 후 계정 정리 코드가 있으나 공통 접속 기록까지 삭제하는 것은 아님 | 학교별 전체 자료 목록에 포함해 별도 확인 |
| 파기 목록·파일 부재 결과·복원 차단 표식 | 파기 증빙과 재등장 방지 | 활동 내용 없이 무작위 객체 번호·처리 범위·시각·상태 보존 | 최소 보관 기간과 최종 원장 종료 기준 미정 |
| 백업·내보내기·종이·담당자 기기 복사본 | 복구 또는 승인된 제출 | 이번 로컬 파일 파기가 외부 사본까지 삭제하지 않음 | 위치·기한·책임자·파기 증빙 미정 |

보관의 시작은 수업의 명시적 종료와 코드 이용 만료 중 먼저 도래한 시점이다. ‘사진’, ‘활동’, ‘운영’은 각각 기한을 계산하며 운영 기한은 앞의 두 기한보다 짧게 등록할 수 없다. 실제 수집에서는 목적 달성 시점·법령상 예외 보존 등도 학교가 검토하여 정책을 확정해야 한다.

현재 썸네일이나 별도 파생 이미지는 생성하지 않는다. 앞으로 생성한다면 모든 파생본을 소유 수업과 원본에 연결해 같은 파기 목록에 넣고 실제 부재를 검증하기 전까지 활성화하지 않는다.

## 3. 학교 제출 흐름

**현재 기본 제출 범위는 개인 원문이 없는 수업 운영 확인이다.** 코드 학생을 자리 번호나 이름만으로 학교 명단에 연결하지 않는다. 코드 학생의 담임용 사후 개인 조회, 계정 합치기, QR 진로 카드, 수업 종료 후 교사의 학생 성찰 대리 저장은 이번에 제공하지 않는다.

| 순서 | 담당 | 확인할 내용과 결과 |
|---|---|---|
| 수업 전 범위 확정 | 학교 담당자·모아킷 책임자 | 학교·수업·수신 담당자·목적·처리 근거·보관 기간·제공 필드·전달 방법을 문서화. 위탁인지 제3자 제공인지 실제 역할에 맞춰 검토 |
| 학생 안내 | 학교·담당 강사 | 쉬운 말로 임시 처리, 장기 기록, 사진을 구분. 선택 거부로 활동에서 제외하지 않음. 필요한 보호자 절차 완료 여부를 학교가 확인 |
| 수업 진행 | 학생·담당 강사 | 본인이 구상·답장·성찰을 입력. 강사는 출석·제작 사실·단계·저장 여부만 확인. 미완료·결석·예시 대체를 완료한 또래 교류와 구분 |
| 제출안 작성 | 담당 강사 | 수업명·일시·프로그램/카드 버전·실시 활동·참여/완료 집계·예시 대체 여부·미완료 사유의 필요한 범위만 정리. 이름·작품 사진·원문 성찰·접속값 기본 제외 |
| 개인 내용이 꼭 필요한 경우 | 학교 개인정보 담당자·학생 | 별도 제공 근거, 본인 확인, 수신자 권한, 필요한 필드, 본인 검토를 먼저 확정. 코드 학생의 자동 사후 제공은 구현되지 않았으므로 화면 권한을 넓혀 대체하지 않음 |
| 전달 | 승인된 담당자 | 수신자와 문서 버전을 확인하고 학교가 승인한 전달 수단 사용. 단체 채팅·공개 URL·공용 폴더로 자동 배포하지 않음 |
| 수신 확인·정리 | 학교 수신 담당자·모아킷 관리자 | 전달 범위·일자·수신 확인과 사본 보관 기한을 기록. 개인 원문을 제출 로그에 중복 복사하지 않음 |
| 기한 후 파기 | 시스템별 책임자 | 광장 파일·DB, 진로기록 원본, 백업, 내보내기, 종이를 나누어 증빙. 일부만 끝났다면 남은 범위를 명시 |

학교 계정 기록은 기존 `moakit_accounts.record_access`와 공통 `career_student_id` 규칙을 따른다. 이번 광장 시험은 코드 학생 경로이며, 기존 학교 계정 규칙을 새로 만들거나 확대하지 않았다. 학교 계정 화면에 접근할 권한이 있다는 사실만으로 코드 학생의 원문을 학교에 제공할 근거가 생기지는 않는다.

교사는 실제로 확인한 출석·제작·전달 사실만 확인한다. 학생이 하지 않은 AI 활용, 대체 활동의 또래 교류, 학생 성찰의 사실성을 임의로 인증하지 않는다. 학교 제출 내용은 생활기록부 등재나 공식 평가의 자동 승인을 의미하지 않는다. 별도 현장 확인이 없으면 ‘운영 집계’ 또는 ‘학생 본인 작성’으로 표시한다.

### 제출안의 빈 서식

| 항목 | 확정·기입할 값 |
|---|---|
| 학교 / 수업 / 수업일 | 학교 담당자가 확정 |
| 프로그램 / 카드 버전 / 실시 활동 | 사용한 승인 버전과 실제 실시 내용 |
| 참여 / 완료 / 미완료 인원 | 실제 진행 현황. 비기록 활동 완료와 진로기록 저장을 분리 |
| 교류 형태 | 또래 교류·예시 대체·종이 확인을 구분 |
| 포함할 개인 항목 | 기본 없음. 필요하면 승인 문서와 필드 목록 |
| 본인·교사 확인의 범위 | 학생 작성 / 강사 관찰 / 미확인 구분 |
| 수신자 / 전달 수단 / 전달일 | 학교가 승인한 담당자와 방법 |
| 사본 보관 종료 / 파기 책임자 | 학교와 모아킷 각각 기입 |
| 근거·계약·안내 문서 버전 | 실제 검토·승인 문서 참조 |

## 4. 역할별 책임과 현장 준비

| 주체 | 맡아야 할 일 | 현재 상태 |
|---|---|---|
| 학교 책임자·개인정보 담당자 | 처리 근거, 학생·보호자 안내, 학교 수신자, 학교의 기록·종이 보관, 권리 요청 창구 확정 | 지정·검토 필요 |
| 모아킷 운영 책임자 | 계약상 역할, 재위탁·제공 범위, 시스템별 기간·원본 파기 절차, 장애·권리 요청 접수·회신 책임 | 운영 승인 필요 |
| 담당 강사 | 선택 존중, 작품만 촬영, 기기 재발급 본인 확인, 결석·제작 사실 확인, 미전송 자료·종이 활동 관리 | 시험 기능 구현, 현장 교육 필요 |
| 시스템 관리자 | 전용 저장소·권한·파기 실행·실패 재시도·복원 재적용·증빙 확인 | 로컬 시험 구현. 운영 저장소·자동 실행은 미도입 |
| 학교 제출 담당자 | 최소 항목 작성, 수신자 확인, 검토본 전달과 사본 파기 | 역할 지정 필요. 자동 전송 없음 |
| 외부 AI 제공사·저장소 사업자 | 승인한 입력·위치·처리 조건·보관/학습 정책·국외 처리·재위탁을 계약에 반영 | 제공사·모델 미선정. 이번 시험 실제 외부 AI 호출 0회 |
| 비용·현장 담당자 | 강사비 지급 주체·기준, 키트 구매·안전 안내, 기기·충전·망, 활동지 인쇄·회수·폐기 책임 | 학교별 확정 필요 |

향 목록·배합·알레르기 등은 실제 키트 안내와 운영 승인을 따라야 한다. 시험용 재료 선택지는 실제 제작 안내가 아니다. 강사용 슬라이드 원문은 비공개 등록 방식이며 공개 정적 파일이나 이 문서에 포함하지 않는다.

## 5. 권리 요청과 사고 처리

요청 접수자는 학교와 모아킷의 확정 연락 창구로 요청을 받고, 공개 자리 번호만으로 본인을 판단하지 않는다. 사진 요청은 우선 조회를 차단하고 파일별 파기 결과를 확인한다. 원본 기록·사본 요청은 담당 시스템으로 이관하여 처리 범위와 남은 자료를 회신한다. 조회 차단, 연결 해제, 정정본 추가를 원문 파기로 설명하지 않는다.

파일 파기가 실패하면 원문을 로그나 티켓에 첨부하지 않고 작업 번호·범위·실패 상태를 전달한다. 관리자는 같은 작업을 재시도하고 파일 부재를 확인한다. 타인 작품 연결 또는 잘못된 전시는 우선 노출을 중지하고 담당 강사·관리자가 대상과 이력을 확인한다. 학교 보고·유출 판단·통지 필요 여부는 지정된 책임자가 사실관계를 확인한다.
