# 광장 3단계 리허설 안내

작성일: 2026-10-04. 기준 브랜치: `feat/plaza-stage3-20261004`.

실제 학생 대신 가짜 참여자로 수업 순서와 복구 동작을 확인하는 안내다. 이번 단계는 리허설 준비까지이며, 실제 교실에서 135분 수업을 진행했다는 뜻은 아니다. 실제 학생 기록·사진 수집은 4단계 검토와 운영 승인 전 열지 않는다.

## 시험 환경 준비

새 빈 로컬 PostgreSQL DB와 저장소 밖 새 비공개 사진 폴더를 사용한다. 이전 시험 DB에 setup을 반복 적용하지 않는다. 운영 주소, Vercel 환경, 표식이 다른 DB·폴더에서는 실행이 거절된다.

```text
DATABASE_URL=postgresql://…@127.0.0.1:<port>/plaza_test_stage3
PLAZA_STAGE1_TEST=1
PLAZA_STAGE2_TEST=1
PLAZA_STAGE3_TEST=1
PLAZA_TEST_ID=<새 UUID>
PLAZA_TEST_STORAGE_DIR=<저장소 밖 새 절대 경로>
PLAZA_SETUP_CONFIRM=disposable-local-test
PLAZA_SYNTHETIC_KIT=1
PORT=3999
SUPERADMIN_PASSWORD=<이번 시험용 무작위 비밀번호>
PLAZA_TEACHER_MATERIAL_PATH=<선택: 별도로 받은 비공개 교안 JSON>
```

`node scripts/plaza-stage3-setup.js`를 실행하면 1·2·3단계 수동 SQL과 가짜 키트 A/B를 새 시험 DB에 준비한다. 시험 강사 계정과 수업 코드는 비공개 사진 폴더의 `fixture.json`에서 확인한다. 이 파일과 접속 쿠키를 저장소·공유 문서에 복사하지 않는다. 교안 경로를 생략했다면 자료를 만든 강사가 앱에서 비공개 교안을 등록할 수 있다.

## 강사가 단계를 넘기는 연습

1. 같은 환경에서 `node server.js`를 실행한다. 시험 강사로 `/class`에 로그인해 ‘광장 수업 진행’을 연다.
2. 별도 터미널에 같은 시험 환경과 `PLAZA_REHEARSAL_CONFIRM=synthetic-only`를 설정한다. `node scripts/plaza-rehearsal.js --prepare 5`로 가짜 참여자 5명의 구상과 간판을 만든다. 1~30명을 지정할 수 있다. 비어 있는 시험 광장에서만 가능하다.
3. 강사 화면에서 제작 대기 → 작품 확인 순서로 진행한다. `node scripts/plaza-rehearsal.js --continue`를 실행하면 현재 단계에서 가능한 가짜 활동을 진행한다.
4. 광장을 열고 다시 `--continue`를 실행하면 요청·답장·반응을 진행한다. 돌아보기를 열고 다시 실행하면 가짜 참여자가 성찰과 최종 기록을 확인한다. 이미 완료된 활동은 건너뛴다.
5. 강사 화면의 또래 교류 완료·대체 완료·기록 저장·미완료 수를 확인하고 종료한다.

도구는 정상 입장·광장 API를 사용하고 학생·기록 표에 활동을 직접 삽입하지 않는다. 가짜 학생·작품·가게·성찰에 리허설임을 표시하고 제작 결과는 ‘제작하지 않음’으로 남긴다. 접속 파일 `rehearsal-clients.json`은 비공개 시험 폴더에 파일 권한 600으로 보관한다. 준비 도중 중단됐다면 강사 화면에서 만들어진 자리부터 확인한다. 이 도구는 부분 생성 상태를 지우거나 학생 자리를 자동으로 새로 만들지 않는다. 처음부터 연습할 때는 별도의 새 시험 환경을 준비한다.

가짜 접속 파일은 실제 학생 브라우저로 옮기지 않는다. 기기 교체 시험은 강사 화면의 ‘기기 접속 재발급’으로 수행한다. 교체한 봇은 예전 접속 파일로 계속할 수 없으므로 자동 전체 흐름 시험과 수동 교체 연습을 별도 시험 환경에서 진행한다.

## 자동 장애 시험

새 setup 직후, 별도 앱 서버를 켜지 않은 상태에서 `node scripts/plaza-stage3-verify.js`를 실행한다. 이 스크립트가 시험용 장애 어댑터를 설치한 서버를 같은 프로세스에서 시작한다. 일반 앱에는 장애 주입 API·관리 버튼·환경변수 스위치가 없다. 외부 AI는 호출하지 않는다.

검증 내용은 접속 재발급·만료·추측 제한, 응답과 쿠키 유실, 지연 중복 제출, 사진 저장 실패·전송 중 옮기기, 결석 전후 배정, 대체·종이 출처, AI 오류·허용되지 않은 응답·8초 제한·실행 중 기기 변경, 30개 접속과 1인 대체 흐름이다. 시험 결과만 stdout에 출력하고 연결 비밀값은 출력하지 않는다.

현재 Work 환경에서는 일반 PostgreSQL 서버와 브라우저 실행이 제한되어, 저장소 밖의 PGlite/PostgreSQL 엔진·앱 서버·HTTP 시험을 한 Node 프로세스에서 실행했다. 이 방식의 앱 DB 풀은 1개 연결이다. 실제 여러 PostgreSQL 연결의 경합 시험과 실기기 검증은 별도로 해야 한다.

## 실제 기기에서 남은 복구 연습

| 상황 | 조작 | 성공 기준 |
|---|---|---|
| 기기 교체 | 두 브라우저에서 같은 수업 접속, 강사가 대상 확인 후 재발급 | 이전 기기의 광장·일반 기록·사진 접근 차단. 새 기기의 자리·가게·구상·기록 연결 유지 |
| 연결값 응답을 못 받음 | 같은 재발급 요청 재확인 후 필요하면 새로 재발급 | 중복 발급하지 않음. DB에서 원문을 복원하지 않음. 새 연결값만 사용 가능 |
| 카메라 거부 | 카메라 권한 거절 후 사진 선택 사용 | 촬영 대상 유지, 실패를 서버 저장으로 표시하지 않음 |
| 사진 응답 유실 | 촬영 중 네트워크 차단 후 복구 | 같은 촬영 번호로 확인. 이미 저장됐다면 현황 조회로 완료 확인 |
| 사진 대상 오류 | 원래 가게·받을 가게를 확인하고 이동 | 이전 전시가 내려가고 새 대상 확인 뒤 전시. 늦은 옛 업로드가 되살아나지 않음 |
| 새로고침 | 미전송 사진이 있는 화면에서 새로고침 | 이탈 전 안내, 바이트가 사라졌다면 재촬영 필요 표시 |
| 개장 전 결석 | 결석 처리 후 참여 명단 확인·개장 | 결석 학생 자리·자료는 유지하고 방문 배정에서 제외 |
| 요청 후 이탈 | 요청을 받은 학생 결석 처리 | 상대·메시지 보존. 필요한 답장만 사유 있는 예시로 대체 |
| 늦은 복귀 | 복귀 처리 후 접속 재발급 | 시작한 교류 보존, 비어 있는 교류만 배정·대체 |
| 인터넷 장애 | 미리 받은 종이 활동지로 진행 | 종이는 서버 미저장 표시. 재접속 후 본인이 확인한 교류만 입력. 종료 뒤 대리 저장하지 않음 |
| 탭 복귀·뒤로 가기 | 화면 잠금·앱 전환·bfcache 복귀 | 권한 재확인 전 개인 내용 감춤. 이미 내려받은 화면 회수를 보장하지 않음 |

실기기별 화면 크기, 카메라 방향·권한, 한글 조합 입력, 강사 연속 촬영 속도, 교실 Wi-Fi, 다중 DB 연결의 지연을 기록한다. 이 문서만으로 실제 수업 적합 판정을 내리지 않는다.
