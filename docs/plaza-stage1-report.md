## 현재 상태

**1단계 기능 구현과 서버 연결 시험을 마쳤다. 화면·실제 기기 카메라 검증은 환경 제한으로 남아 있다. 2단계는 시작하지 않았다.**

| 1단계 항목 | 구현·확인한 내용 |
|---|---|
| 코드 입장 | 기존 `/api/join`, 실제 수업과 `session_items` 배정을 통과한 학생만 광장 입장 |
| 자리·학생·가게 연결 | 서버가 만든 참여자·학생 UUID·가게 UUID를 연결. 자리는 표시·촬영 순서이며 복구 열쇠가 아님 |
| 구상 저장 | 손님·짧은 구상·작품명·가게명을 `plaza_drafts`에 저장. 버전 충돌과 동일 시도 다른 내용은 409 |
| 잠시 멈춤 | 강사의 ‘제작하러 가기’는 광장만 paused로 바꿈. 수업 코드·초안·가게 유지. 미완료 인원 유지 |
| 재입장 | 같은 로그인에서도 먼저 ‘내 구상 이어가기’를 선택. 코드 재입장 후에도 현재 접속 비밀값이 있어야 같은 참여자로 복귀 |
| 이전 접속 차단 | 복귀하며 이전 게스트 로그인과 진로기록 이어가기 연결을 회전. 이전 일반 기록 API 접근까지 차단 |
| 다음 학생 | ‘새 학생으로 입장’은 확인 후 새 참여자로 시작. 기존 가게·구상·사진을 잇지 않음 |
| 강사 사진 연결 | 촬영할 때 가게·참여자·연결 버전·촬영 번호를 고정. 다음 자리로 이동해도 업로드 대상 유지 |
| 사진 저장 확인 | 예약 → 비공개 파일 쓰기 → 다시 읽어 해시 확인 → 현재 전시본 연결. 재전송 중복 방지, 느린 이전 촬영이 새 사진을 덮지 않음 |
| 사진 접근 | 학생은 1단계에서 자기 작품만 인증 서버 경유 조회. 직접 파일 URL·Storage 주소 미제공, private/no-store |
| 종료 | 되돌릴 수 없는 closed. 게스트 로그인·광장 권한·기존 진로기록 연결 폐기. 미완료 기록을 대신 생성하지 않음 |

## 실제로 실행한 검증

- `npm run check`: 통과.
- `npm test`: **156개 통과**. 기존 151개 + 광장 5개. 구문, 기존 기능, 시험 환경 차단, 초안 검증, JPEG 검사/메타데이터 제거, 파일 중복, 인증 갱신 화면 보존 분기 포함.
- `scripts/plaza-stage1-verify.js`: **HTTP·SQL 확인 54개 통과**. 실제 `server.js`, `lib/api.js`, `pg`와 새 광장 서비스에 HTTP로 요청했다. DB 쿼리나 인증 API를 가짜 응답으로 대체하지 않았다.
- 주요 거절: 미로그인, 교차 출처 쓰기, 중복 자리, 오래된 초안 버전, 다른 학생 초안·사진, 비담당 instructor, partner, 기존 자료 잠금·비공개, 가짜 JPG, 종료 후 재개.
- 중간 구상·사진·수업 종료를 거친 뒤 `career_log.records`는 **0건**이었다. 최종 기록 발행은 2단계 전까지 광장 자료에 한해 기존 기록 API에서도 거절한다.
- 새 표 **9개 RLS 활성화**, `anon`/`authenticated`의 직접 SELECT 권한 없음 확인.
- 신규 앱 의존성·프레임워크·lockfile 변경 없음. 기존 HTML sandbox, 공통 계정 규칙, 향기 타로 앱은 변경하지 않았다.

### 시험 환경의 실제 범위

| 항목 | 이번에 사용한 것 |
|---|---|
| DB | 현재 작업 공간의 전용 임시 PostgreSQL 18.3 **PGlite 0.5.8** 엔진. 일반 PostgreSQL 설치가 현재 실행 환경의 사용자·파일 권한 제한으로 불가능해 검증용으로만 사용 |
| 접속 | `127.0.0.1`의 전용 포트. DB 이름 `plaza_test_stage1`, 무작위 시험 표식과 DB 이름을 매 트랜잭션에서 대조 |
| 트랜잭션 | 앱의 기존 `pg` 연결과 `withTransaction` 사용. 시험 풀은 1개 연결로 직렬화. **일반 PostgreSQL 여러 연결 간 경합·교실 부하를 검증한 것은 아님** |
| 사진 | 저장소 밖 전용 임시 폴더. 무작위 시험 표식 확인, 폴더 0700·파일 0600, 공개 정적 경로 없음. 기존 media 버킷 사용 없음 |
| 학생·강사 | 무작위로 만든 시험 계정. 운영 학교 명단·학생 사진·계정 복제 없음. 공통 계정 표 생성·수정 없음 |
| 외부 호출 | 실제 AI 호출 없음. Supabase 운영 DB·Storage 쓰기 없음 |

PGlite 도구는 작업 공간의 일회성 검증 도구이며 `package.json`의 앱 의존성에는 들어 있지 않다. 저장소의 준비·검증 스크립트는 기존 `pg`만 사용하므로 별도 로컬 PostgreSQL에서도 실행하도록 작성했다.

### 통과로 표시하지 않은 것

- `agent-browser`는 daemon 시작에 실패했다. 기존 헤드리스 Chromium도 `socket() failed: Operation not permitted`로 실행되지 않았다. 따라서 **노트북·태블릿·모바일 실제 렌더링, 한글 조합 입력, 실제 카메라·촬영 버튼의 브라우저 동작은 미검증**이다.
- 인증 갱신에서 광장 화면을 유지하는 분기는 단위 테스트로 확인했지만 실제 DOM·IME·화면 잠금 복귀 시험을 대체하지 않는다.
- 이번 파일 저장소는 명시적인 **로컬 시험 전용 구현**이다. Supabase 비공개 버킷 연결, 짧은 서버 내부 URL, 실제 저장소 만료·파기는 구현 완료로 표시하지 않는다.
- 실제 반의 여러 기기, 응답 순서 뒤집힘·오프라인 장기 복귀·연속 재촬영·사진 옮기기 종합 시험은 3단계 범위다.
- 다른 기기로 강사가 접속을 재발급하는 화면, 교류·AI·돌아보기·진로기록 최종 발행·교안·광장 배경은 구현하지 않았다.

## 재실행 방법

먼저 별도의 비어 있는 로컬 DB `plaza_test_…`를 준비한다. 운영 연결 문자열을 사용하지 않는다. 환경변수는 저장소에 커밋하지 않는다.

| 환경변수 | 값의 조건 |
|---|---|
| `DATABASE_URL` | localhost 또는 127.0.0.1의 `plaza_test_`로 시작하는 새 DB |
| `PLAZA_STAGE1_TEST` | `1` |
| `PLAZA_TEST_ID` | 새 무작위 UUID |
| `PLAZA_TEST_STORAGE_DIR` | 아직 존재하지 않는, 저장소 밖 절대 경로 |
| `PLAZA_SETUP_CONFIRM` | `disposable-local-test` |
| `SUPERADMIN_PASSWORD` | 무작위 시험 비밀번호 |
| `PORT` | `3999` |

1. `npm ci`
2. 위 시험 설정에서 `node scripts/plaza-stage1-setup.js`를 **명시적으로** 한 번 실행한다. 비어 있지 않은 DB는 거절한다.
3. 같은 환경변수로 `node server.js`를 실행한다.
4. `node scripts/plaza-stage1-verify.js`를 실행한다. 검증 마지막에 시험 광장을 종료하므로 다시 검증하려면 새 빈 시험 DB를 준비한다.
5. 실제 브라우저 확인은 검증 스크립트로 종료하기 전에 진행한다. 비공개 시험 사진 폴더의 `fixture.json`에 시험 강사 접속·수업 코드·광장 경로가 있다. 이 파일을 커밋·외부 공유하지 않는다.

학생: `/class#/plaza/<roomId>`, 강사: `/class#/plaza-teacher/<roomId>`. 학생은 먼저 기존 코드 입장, 강사는 기존 계정 로그인을 통과해야 한다. 자료 이름·링크 문자열로 광장을 판별하지 않는다.

## 남은 1단계 확인과 다음 단계 경계

현재 운영 사이트에서 사용할 수 있는 완료 배포물이 아니다. **일반 PostgreSQL과 실제 브라우저·기기에서 위 연결 흐름을 다시 확인하는 것이 남은 1단계 확인**이다. 특히 화면 전환 중 미전송 촬영은 메모리에서 사라질 수 있어 ‘재촬영 필요’로 다루며, 새 입장 응답 유실에 대한 복구·기기 변경 종합 시험은 3단계에 확장한다.

향 목록을 임의로 채우지 않았다. 실제 키트 확인, AI 제공사·모델·상한, Cloud 시험 DB·비공개 버킷은 미정이다. 이번 요청을 Cloud 리소스 유료 생성·운영 적용·자동 SQL 적용 승인으로 확대하지 않았다.

`career_log.records`의 UPDATE/DELETE, 공통 계정 변경, 운영 브랜치 병합, 운영·미리보기 배포는 하지 않는다. 추가 단계는 사용자의 다음 요청 뒤에만 진행한다.
