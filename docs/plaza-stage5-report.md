## 완료 범위

사용자의 진행 요청에 따라 QR 진로 카드와 다른 프로그램 카드의 **별도 로컬 시험 구현**을 완료했다. 0단계 원문과 설계는 수정하지 않았다. 실제 시범 수업은 진행되지 않았고 피드백·실제 키트 목록을 받지 않았으므로, 시범 피드백 반영이나 운영 준비 완료로 판정하지 않는다.

| 항목 | 구현 결과 |
|---|---|
| QR 진로 카드 | 최종 기록이 실제 저장된 후 카드 확인·인쇄 진입. 기존 내 진로기록 목록에서도 진입 |
| 열람 | 기록 ID를 아는 것만으로 열리지 않음. 매번 기존 본인 학생 번호 또는 담당 강사·관리자의 기록 조회 범위 확인 |
| 인쇄 | 저장된 과정·결과물·돌아보기를 표시하고, 인쇄 버튼을 누르면 권한을 다시 조회한 뒤 인쇄 호출 |
| 공통 프로그램 | 기존 조향사 v2 보존, 표시 문구를 포함하는 조향사 v3와 공예디자이너 v1 추가 |
| 카드 등록 | 허용 데이터 구조·길이·선택지 ID·재료 참조 검증. 같은 버전의 다른 내용 거부, 동일 내용 재시도는 같은 ID |
| 광장 준비 | 실제 담당 수업·자료·등록 버전·자리 수 사용. 배정·학생 공개·잠금·수업 기간 검사. 기존 광장의 버전·자리 수 덮어쓰기 및 종료 후 재개 금지 |
| 키트·교안 | 실제 카드는 키트 확인 대기. 명시적 가짜 키트 설정에서만 시험 재료 제공. 강사 교안은 기존 비공개 경로에 별도 등록 |
| 보관 관문 | 새 광장도 관리자가 시험 보관 기간을 등록하기 전 입장 불가. 실제 수집 차단 유지 |

## QR이 의미하는 것

QR은 `/class#/plaza-record/<record UUID>`를 담은 기록 주소다. 학생 UUID·이름·접속 비밀값·자유 서술은 QR에 넣지 않는다. JSON 응답은 `private, no-store`, `Vary: Cookie`, `Referrer-Policy: no-referrer`를 사용하며, 카드에는 사진과 원본 내부 메타데이터를 보내지 않는다. QR SVG는 이미 설치된 `qrcode`로 생성한다. 새 의존성은 추가하지 않았다.

본인 조회는 기존 `career-log`의 학교 계정 `career_student_id`, 일반 계정 연결, 세션에 묶인 코드 학생 연결 규칙을 그대로 사용한다. 강사·관리자도 기존 `teacher_ids`와 역할 범위 안에서만 읽는다. 진로업체 담당자의 허용 경로는 넓히지 않았다.

수업 코드 학생은 수업 종료·만료 또는 기기 재발급으로 접속이 폐기되면 예전 QR을 열 수 없다. 같은 수업 코드와 같은 이름·자리로 다시 들어오는 것은 본인 인증이 아니다. 기존 일회성 기기 연결 절차를 완료했을 때만 아직 유효한 접속으로 다시 읽는다. **수업 뒤 영구 열람권이나 학교 계정 자동 연결을 제공하지 않는다.** C11의 장기 계정 연결은 별도 검토 사항으로 남겨 두었다.

현재 주소는 서버의 `PORT`와 고정된 `127.0.0.1`로 만든 로컬 시험 주소다. 요청의 Host나 전달 헤더로 QR의 목적지를 바꾸지 않는다. 휴대전화에서 스캔하여 운영 서비스에 접속하는 용도로 발급한 QR이 아니다. 인쇄 카드에도 이 제한을 표시한다.

기록이 정정되면 예전 QR에서 오래된 원본을 다시 노출하지 않는다. 기존 내 진로기록 목록에서 현재 기록을 확인해야 한다. QR 기능은 `career_log.records`에 쓰지 않는다. 시험의 정정 사례도 원본 UPDATE/DELETE 없이 `supersedes_id`를 가진 새 레코드로 만들었다.

탭이 숨겨지거나 연결이 끊기면 카드 본문을 지운다. 돌아오면 서버에서 다시 확인한다. 화면을 떠난 뒤 도착한 응답은 카드를 되살리지 않으며, `localStorage`와 `sessionStorage`에 카드나 등록 초안을 남기지 않는다. 인쇄 허용은 새 권한 확인을 마친 카드의 인쇄 호출 동안만 설정하고 해제한다.

## 프로그램 카드 확장

`lib/plaza-card-catalog.js`는 데이터만 받는다. 직업·제품·재료 안내 문구, 문제·손님, 재료·허용 조합, 소개·요청·답장·반응, 이름 후보, 기존 3문항의 성찰 도움 문장을 검증한다. 추가 질문, 임의 속성, 교안, HTML, 실행 스크립트, URL, 임의 시스템 프롬프트, 없는 재료를 참조하는 조합은 거부한다.

공예디자이너의 문제는 사람마다 다른 쓰임과 취향을 배려하는 공예품 소개다. 실제 재료·제작법·사용량·안전 효능을 추측해 넣지 않았다. 시험용 A/B 재료는 가짜라고 표시한다. 공예 수업도 같은 인증·사진·방문·성찰·저장 코드를 사용한다. 조향사 전용 문구는 카드의 표시 항목으로 옮겼으며, 이전 v2 카드에는 기존 문구를 유지한다.

카드 버전과 광장 등록은 기존 `plaza_program_versions`, `plaza_rooms`를 사용한다. 새 DB 표나 자동 마이그레이션을 추가하지 않았다. `review_status`는 계속 `test-only`다. 카드 등록 권한은 본인이 만든 자료의 강사와 관리자에게만 주며, 광장 준비는 담당 수업 권한도 함께 확인한다. 실제 활성화나 보관 승인 값을 등록 화면에서 바꾸는 기능은 없다.

화면 시험에서 등록 후 새 버전 선택 목록이 갱신되지 않는 변수 참조 오류를 발견해 수정했다. 목록 재조회에 실패했을 때 저장 성공 문구가 그 실패를 덮지 않도록 처리했으며, 확인되지 않은 선택지로 계속 진행하지 않는다.

시험 엔진은 별도 로컬 PGlite/PostgreSQL 18.3 호환 환경이다. 실제 학생 0명, 외부 AI 호출 0회다. 실제 브라우저의 화면 배치·프린터 출력·카메라 스캔은 확인하지 못했다. 기존 환경에서 Chromium이 프로세스 소켓 제한으로 실행되지 않았으므로 JSDOM을 실제 브라우저 확인으로 부르지 않는다.

## 남아 있는 운영 조건

1. 실제 시범 수업 피드백, 실제 키트 목록·허용 조합·그림 권리·교안 검토.
2. D8/D9/D10의 원본·백업·내보내기 보관/파기 절차, 학교 제공 범위와 담당 권한 확정.
3. 장기 학교 계정 연결을 원할 경우 별도 본인 확인·연결 설계와 승인. 이름·자리 자동 병합 금지.
4. 승인된 시험 환경에서 실제 기기 QR 스캔, 긴 기록의 인쇄 페이지 나눔, 인쇄 후 공유 기기 초기화 확인.
5. 실제 수집·배포를 위한 별도 관문 검토. 이번 구현은 해당 관문을 통과시키지 않는다.

`teacher-s-project`, 공통 학교 계정 규칙, 기존 향기 타로, 기존 기록 원본은 변경하지 않았다. 운영 브랜치 병합·운영/미리보기 배포는 하지 않는다. `vercel.json`에 5단계 브랜치 자동 배포 차단을 추가했다. 여기서 5단계 시험 개발을 멈춘다.
