## 완료 범위

**조향사 전체 활동의 코드 구현과 격리된 시험 검증을 마쳤다. 실제 키트·외부 AI·실제 기기 검증은 아래와 같이 남아 있다. 3단계는 진행하지 않는다.**

| 흐름 | 구현한 동작 |
|---|---|
| 구상 | 손님 → 시향한 재료 선택 → 구상 두 안 → 한 안 선택 → 허용 조합 또는 소개 수정 → 이름 후보 수정 → 간판 저장 |
| 학생 수정 | 구상이나 답장 초안이 그대로면 완료로 인정하지 않는다. 이름 후보도 학생이 바꾼 값을 저장한다. |
| 제작·복귀 | 기존 제작 대기·명시적 이어가기 유지. 실제 결과를 구상대로/변경/미제작으로 직접 확인한다. |
| 광장 | 생성한 공방 배경과 빈 가게 틀 위에 HTML 간판·전시·버튼을 배치한다. 전체 위치, 내 가게·방문 가게 확대, 이름 목록을 함께 제공한다. |

| 교류 | 요청 카드 한 개 → 받은 요청의 답장 초안 한 번 → 학생 수정 답장 → 받은 답장에 선택 반응. 전송 후 확정하고 동일 시도 중복 방지. |
| 돌아보기 | 원문의 세 질문 그대로 제공. 짧은 직접 입력과 선택 문장 도움을 제공한다. |
| 최종 기록 | 서버가 확정 활동으로 기존 3칸과 출처 정보를 구성. 학생이 확인하면 내용·해시·시도 번호를 고정하고 저장한다. 개인별 최종 접수와 기록 INSERT를 같은 트랜잭션에서 처리한다. |
| 강사 현황 | 구상·제작 확인·요청·답장·반응·성찰·기록 저장 현황, 또래 완료/대체 완료를 분리한다. 미완료 종료 시 사유를 남기고 학생 기록을 대신 생성하지 않는다. |
| 교안 | 담당 강사 전용 발표 화면과 비공개 교안 등록·조회. 별도 전달한 `perfumer-teacher-material.json`은 16장, 앞 6장 직업 소개 10분, 이후 원문의 수업 진행 안내다. |

## 데이터와 권한

- 기존 `career-log` 학생 INSERT 로직을 내부 함수로 분리해 일반 저장과 광장 최종 저장에서 공유했다. `submission`, advisory lock, `source=job`, 실제 `job-deck:<id>`·`job-class:<id>`, 서버가 확인한 학생 UUID와 `job:<student_uuid>:<attempt_id>`를 유지한다.
- `career_log.records`를 UPDATE/DELETE하지 않는다. `verification_status` 등은 기존처럼 null이며 강사 확인 기록으로 위장하지 않는다. 확정 기록에는 다른 학생의 전체 답장·성찰·연결 식별자·사진 URL/바이트를 복제하지 않는다.
- 일반 진로기록 API로 광장 자료를 우회 저장하는 통로는 계속 차단한다. 최종 저장은 학생의 광장 접속과 확정 접수를 다시 확인한다.
- 전시 응답은 가게 공개 ID, 가게 이름, 작품 이름, 선택한 소개, 인증 사진 경로만 제공한다. 자리·학생 번호·기록 번호·AI 입력·개인 성찰은 제외한다.
- 개장 이후 이번 반의 전시 사진은 인증 프록시로 조회한다. 개장 전에는 기존 본인/담당 강사 제한을 유지한다. 종료·자료 잠금·수업 만료 시 사진과 교안도 차단한다.
- `db/plaza-stage2.sql`에 활동·AI 실행·방문·최종 접수·비공개 교안 표 5개를 수동 시험용으로 추가했다. RLS를 활성화하고 PUBLIC/anon/authenticated 직접 권한을 제거했다. `lib/db.js` 자동 적용에는 넣지 않았다.
- 교안 전체 원문은 공개 저장소와 정적 파일에 없다. 비공개 파일을 담당 강사가 앱에서 등록하거나 시험 준비 스크립트로 가져온다. 단순히 학생용 자료의 표시만 숨기는 방식이 아니다.

## AI의 구현 상태

실제 제공사·모델·키·비용 상한은 선택하지 않았다. 앱 실행 시 외부 AI를 호출하지 않으며 준비된 예시가 기본이다. 서버 서비스에 주입할 수 있는 제공사 어댑터 경계, 단일 실행 예약, 시간 제한, 응답 검증, 실패·중단 시 예시 복구 구조를 구현했다. 제공사 API 연동과 실제 유료 호출 검증은 미완료다.

외부 입력 생성기는 가상 손님, 승인 재료·조합·문구와 선택형 값만 만든다. 학생 이름·번호·자리·가게명·자유 답장·성찰·사진은 포함하지 않는다. 출력은 승인된 조합/문구 ID만 받아 임의 향·배합·효능 문장을 학생에게 전달하지 않는다. 구상 두 개와 답장 한 번을 참여자별로 고정한다.

`call_attempted`와 실제 사용한 `source`를 분리한다. 이번 전체 흐름 시험의 출처는 `example`, 외부 호출 여부는 false다. 예시 활동을 AI 활용으로 기록하지 않는다. 실제 향 목록은 비어 있고 ‘키트 목록 확인 대기’를 유지한다. `PLAZA_SYNTHETIC_KIT=1`로 만든 시험 재료 A/B만 개발 시험에 사용했다.

DB는 임시 전용 `plaza_test_stage2`, 무작위 시험 표식, 루프백 pg 접속과 PGlite 0.5.8/PostgreSQL 18.3 엔진을 사용했다. 사진은 저장소 밖 전용 로컬 파일 폴더에 보관했다. 실제 학생·학교 계정·운영 자료를 복사하지 않았다. 테스트 도구는 저장소 밖에만 설치했으며 앱 의존성·lockfile을 바꾸지 않았다.

HTTP 시험은 실제 API와 SQL을 사용했다. DOM 시험은 별도 jsdom 도구와 가짜 응답으로 클라이언트 상태 전이를 확인한 것으로, 브라우저 렌더링 시험과 구분한다. PGlite 연결 특성상 앱 풀은 1개 연결이었고 여러 DB 연결의 동시성·교실 네트워크를 재현한 것은 아니다.

## 다시 실행하는 방법

아래 환경은 새 빈 로컬 DB와 저장소 밖의 새 비공개 사진 폴더를 요구한다. 운영 DB나 기존 폴더로 바꾸어 실행하지 않는다. DB와 파일의 시험 표식이 맞지 않으면 중단한다.

```text
DATABASE_URL=postgresql://…@127.0.0.1:<port>/plaza_test_stage2
PLAZA_STAGE1_TEST=1
PLAZA_STAGE2_TEST=1
PLAZA_TEST_ID=<새 UUID>
PLAZA_TEST_STORAGE_DIR=<저장소 밖 새 절대 경로>
PLAZA_SETUP_CONFIRM=disposable-local-test
PLAZA_SYNTHETIC_KIT=1
PLAZA_TEACHER_MATERIAL_PATH=<별도로 전달한 비공개 JSON의 절대 경로>
```

1. `node scripts/plaza-stage2-setup.js`: 기존 1단계 빈 시험 DB 준비 후 수동 2단계 SQL과 버전 2 카드를 적용한다. 비공개 교안 경로는 선택 사항이며, 없으면 자료를 만든 강사가 앱에서 등록한다.
2. 같은 시험 환경에서 `node server.js`를 실행한다.
3. `node scripts/plaza-stage2-verify.js`: 비공개 교안이 등록된 시험 fixture로 전체 검증을 실행한다. fixture 계정 정보는 비공개 시험 폴더에만 있다.
4. 브라우저에서는 `/class`에 시험 강사로 로그인해 ‘광장 수업 진행’을 선택한다. 학생은 fixture의 수업 코드로 입장한 뒤 배정된 ‘조향사 광장’을 연다.

현재 Work 실행 환경은 실행 세션 간 localhost 연결에 제약이 있어 DB 엔진·서버·HTTP 검증을 한 Node 실행 안에서 구동했다. 생성 이미지 프롬프트와 배치 좌표는 [plaza-stage2-assets.md](plaza-stage2-assets.md)에 남겼다.

## 저장과 중단

2단계 전용 브랜치에 저장한다. `vercel.json`에서 이 브랜치의 Git 자동 배포를 끈다. 운영 브랜치 병합, 운영 DB 변경, 미리보기·운영 배포는 하지 않는다. 여기서 멈추며 3단계는 다음 요청 뒤 진행한다.
