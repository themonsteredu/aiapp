| 검증 | 결과 | 확인 범위 |
|---|---:|---|
| 전체 구문 검사 | 통과 | `npm run check`, 새 4단계 파일 포함 |
| 기존 단위 검증 | 161개 통과 | `npm test` |
| 4단계 HTTP·DB·실파일 | 85개 통과 | 선택·기록 미생성·권한·사진 삭제 장애·부재 재확인·지연 업로드·기한별 파기·복원·고아 파일·원본 불변 |
| 1단계 회귀 | 54개 통과 | 기존 접속·사진 경로 |
| 2단계 회귀 | 215개 통과 | 전체 활동·최종 원본 저장 |
| 3단계 회귀 | 90개 통과 | 기기 복구·교류 예외·사진 이동·가짜 30명 리허설 |
| 4단계 DOM | 15개 통과 | 선택 기본값·독립 선택·응답 유실 재시도·비기록 완료·사진 실패 표시·관리자 기간 등록 |
| 기존 학생 DOM | 14개 통과 | 입력·포커스 유지, 단계·저장 표시 |
| 기존 복구 DOM | 17개 통과 | 기기 복구·화면 복귀·사진 이동 |

HTTP 검증은 실제 앱의 Node 요청 처리와 PostgreSQL 엔진(PGlite) 및 로컬 파일시스템을 사용했다. 실제 학생·운영 DB·운영 Storage를 사용하지 않았다. 4단계 외부 AI 호출은 0회이며 준비된 예시로 진행했다. 3단계 회귀의 장애용 어댑터 호출도 실제 외부 서비스 호출이 아니다.

검증한 한계: PGlite와 단일 DB 풀 환경은 실제 다중 연결 PostgreSQL 경합 검증을 대신하지 않는다. DOM 검증은 실제 브라우저의 레이아웃·카메라·iPad 촬영 검증이 아니다. 현재 환경에서 네이티브 Chromium 실행이 제한되어 실제 기기 검증을 완료했다고 표시하지 않는다. 운영 오브젝트 저장소·백업·내보내기 삭제도 검증하지 않았다.

## 실제 학생 수집 전에 남은 결정

| 0단계 결정 | 남은 내용 |
|---|---|
| D8 | 운영 자료별 보관 기간, 원본 진로기록의 기존 시스템 파기 절차, 백업·내보내기·파기 증빙 원장 보존과 종료 정책 |
| D9 | 학교별 처리 근거와 안내, 기록·사진 거부 안내, 코드 학생 개인 원문의 학교 제공 범위와 본인 확인 |
| D10 | 위탁/제공 역할, 학생·보호자 안내, 담당자와 권리 요청 창구, 외부 AI·저장소 조건, 강사비·기기·인쇄 책임 |
| 운영 검증·승인 | 실제 키트·실기기·운영 저장소·다중 DB 연결, 자동 파기 실행 주기·실패 알림, 사용자의 운영 배포 승인 |

광장 사진·초안이 파기돼도 기존 게스트·공통 접속 이력, 장기 기록, 백업·학교 제출 사본, 최소 파기 원장은 별도 범위다. UI와 API는 ‘광장 범위 검증 완료’를 사용하며 `whole_system_complete`는 항상 `false`다. 기존 원본의 보호 트리거를 해제하거나 연결 해제를 원문 삭제로 취급하지 않는다.

현재 파기는 관리자 수동 실행이다. 자동 스케줄러가 설치되지 않았다. 종료 후 코드 학생의 학교 계정 연결·담임용 개인 조회·대리 성찰 저장도 추가하지 않았다. 학교 제출 문서는 검토용이며 실제 전송이나 외부 공유를 실행하지 않았다.
