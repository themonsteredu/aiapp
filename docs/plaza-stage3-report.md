**예외 처리 구현과 가짜 참여자 리허설 준비를 마쳤다. 실제 학생을 이용한 수업·실기기 검증은 하지 않았다. 3단계에서 멈추며 4단계는 진행하지 않는다.**

## 구현한 복구 동작

| 상황 | 처리 |
|---|---|
| 기기 변경 | 담당 강사가 참여자를 확인하고 재발급. 이전 광장 권한·로그인·일반 진로기록 이어가기 연결을 폐기하고, 새 기기를 같은 참여자·학생 UUID·가게·구상·기록 접수에 연결 |
| 일회성 연결값 | 서버가 96비트 무작위 값을 생성. DB에는 해시만 저장. 유효기간 최대 5분 또는 수업 만료 시각까지. 사용자별 5회·방별 50회 실패 후 5분 구간 제한. URL·감사 원문·AI 입력에 비밀값을 넣지 않음 |
| 응답 유실 | 새 입장·기기 연결은 쿠키까지 받지 못해도 같은 요청으로 복구. 재발급 재확인은 중복 발급하지 않고 처리 상태만 반환. 원문 연결값을 못 받은 강사는 명시적으로 새 재발급 가능 |
| 사진 실패 | 이전 저장 사진 유지, 같은 촬영 번호로 재시도, 서버 현황 조회로 저장 완료 재확인. 파일 바이트를 잃었다면 재촬영 안내 |
| 사진 이동 | 같은 반의 원래 가게·받을 가게를 강사가 확인. 이전 전시를 먼저 내리고 두 대상 버전을 변경. 저장 사진은 새 객체로 연결하고 전송 중 사진은 새 촬영 번호로 보냄. 지연 중인 옛 업로드는 거절 |
| 결석·중도 이탈 | 출석을 참여자 연결과 분리하고 자리를 유지. 기존 접속 폐기. 개장 전 배정에서 제외하고, 개장 뒤에는 영향을 받은 미시작 방문만 조정 |
| 요청 뒤 결석·늦은 복귀 | 메시지가 있는 방문의 상대·원문 보존. 필요한 답장은 예시·대체 사유를 따로 저장. 복귀 시 빈 교류만 연결하고 이미 진행한 교류를 다시 섞지 않음 |
| 상세 결석 사유 | 강사 자유 서술은 비공개 감사 이력에만 보관. 학생 화면과 최종 기록에는 일반적인 교류 조정 사유만 제공 |
| 중복 제출 | 구상·제작 확인·돌아보기·교류별 요청 접수를 보존. 더 최신 저장 이후 늦게 도착한 옛 요청도 처음 결과를 확인하고 최신 내용을 덮어쓰지 않음. 같은 번호의 다른 내용은 거절 |
| AI 장애 | 단일 호출 예약 유지. 오류·허용되지 않은 응답·8초 제한·실행 중단은 준비된 예시로 복구. 취소 신호 전달. 호출 시도와 실제 사용 출처 분리 |
| 인터넷 장애 | 즉시 개인 화면을 감추고 종이 진행·미저장 안내. 강사가 수업 전에 종이 활동 카드를 준비. 재접속 후 학생 본인이 확인한 교류만 `paper-confirmed`로 입력·기록 |
| 화면 복귀 | 탭 복귀 이후 새 권한 확인을 마쳐야 개인 화면 표시. 복귀 전에 시작한 지연 응답으로 화면을 다시 열지 않음. 입력과 전송 대기 내용은 메모리에 보존 |
| 가짜 참여자 | 빈 시험 광장에 1~30명 준비. 정상 입장 API로 각각 독립 접속. 강사가 단계를 넘기면 CLI로 해당 단계의 가짜 활동 진행 |

강사 화면에 참여자 선택, 접속 재발급, 결석·복귀, 사진 옮기기, 종이 활동 카드 준비를 추가했다. 입력·선택은 주기적인 현황 갱신으로 지우지 않는다. 재발급 연결값은 화면 이탈과 만료 시 제거한다. 종료 확인은 다른 기기에서 시작한 미저장 사진도 포함한다.

## 유지한 경계

- `docs/plaza-plan.md`, 0단계 설계, 모아허브·공통 계정·기존 향기 타로·HTML sandbox 규칙은 변경하지 않았다.
- `career_log.records`는 INSERT만 사용한다. 실제 자료·수업 참조와 서버가 확인한 학생 UUID·attempt_id, 기존 3칸·확정 원문 해시를 유지한다. 출석 변경이나 기기 교체로 확정 기록을 고치지 않는다.
- 일반 만료 게스트 계정 정리가 새 감사 표의 외래키 때문에 막히지 않도록 했다. 계정이 정리돼도 참여자·기록·감사 연결은 보존한다.
- `db/plaza-stage3.sql`은 수동 시험 SQL이다. 출석·사진 버전·방문 이력 필드와 작업 접수·쓰기 접수·재발급·입력 제한 표 4개를 추가한다. 새 표 모두 RLS 및 PUBLIC/anon/authenticated 직접 접근 차단. `lib/db.js` 자동 적용에는 넣지 않았다.
- `PLAZA_STAGE3_TEST=1`은 기존 1·2단계 플래그와 표식 있는 별도 로컬 DB·사진 폴더가 있어야 동작한다. Vercel·운영 DB에는 켤 수 없다. 기존 1·2단계만 켠 환경도 회귀 검증했다.
- 앱 라이브러리·프레임워크·lockfile은 추가하거나 변경하지 않았다. 교안 원문과 시험 계정·쿠키·사진은 공개 저장소에 넣지 않았다.
- 파일 파기는 구현하지 않았다. 이동 전 사진·재촬영본·임시 객체는 추적 가능한 상태로 보존하고 4단계 파기 범위에 남긴다. 이 결과를 실제 학생 데이터 보관 정책의 완료로 보지 않는다.

HTTP 시험은 실제 앱 dispatcher·인증·SQL·로컬 비공개 사진 저장소를 사용했다. DB는 저장소 밖의 PGlite 0.5.8/PostgreSQL 18.3으로 만든 새 `plaza_test_stage3`이며 앱 풀은 1개 연결이다. 30개 HTTP 접속은 확인했지만 여러 DB 연결이 동시에 실행되는 일반 PostgreSQL 운영 부하는 검증하지 않았다.

AI와 저장소 장애는 시험 프로세스에서 주입한 어댑터로 만들었다. 실제 외부 AI 호출은 0회다. 일반 앱은 여전히 제공사·모델·키를 선택하지 않았고 준비된 예시를 사용한다. AI 제공사 시험과 실제 교실 인터넷 품질을 검증했다고 보지 않는다.

DOM 시험은 저장소 밖의 기존 jsdom 도구와 가짜 전송 응답으로 실행했다. 실제 Chrome·Safari 화면, 카메라, 태블릿, 한글 조합 입력, 135분 강사 리허설은 미검증이다. 이 환경의 브라우저 실행 제약 때문에 화면 검증 완료를 주장하지 않는다.
