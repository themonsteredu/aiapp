## 0. 이 문서를 사용하는 방법

모든 다음 작업은 [plaza-plan.md](plaza-plan.md)를 먼저 읽고 시작한다. 그 파일은 사용자 요청 원문이고, 이 문서는 그 요구를 구현하기 위한 제안이다. 원문과 충돌하면 원문을 우선하며 임의로 요구를 줄이지 않는다.

이번에 저장하는 것은 이 문서와 원문 문서 두 개뿐이다. 실행 코드, SQL, 그림 파일, 슬라이드 본문, 자료 등록, 계정, DB, 저장소, 환경변수는 만들거나 바꾸지 않는다. 1단계는 사용자가 별도로 요청할 때만 시작한다. 설계의 숫자와 표 이름은 승인 전 제안이며 현재 구현된 기능이 아니다.

먼저 확인한 파일은 다음 여섯 개다. 모두 위 기준 커밋을 기준으로 읽었다.

| 파일 | 설계에 반영한 기존 동작 |
|---|---|
| ../CLAUDE.md | 실제 운영 브랜치, 해시 라우팅, HTML 격리, 브랜드, 공통 계정·담당자 권한 |
| job-career-log.md | 코드 학생의 기기 연결, 기록 규격, 관찰·사진의 지원 범위, 저장 재시도, 화면 재생성 제약 |
| ../lib/career-log.js | identity/start, 서버의 학생 식별, 자료 배정 검사, 필수 글자수, attempt_id 잠금과 중복 방지 |
| ../lib/school-registry.js | 학교 계정 중심의 관찰 기록, recordLevel, 본인·담당자 사진 조회, 원본 보존 |
| ../lib/storage.js | 기존 미디어 저장소, 기본 3시간 서명 링크, 저장소 미설정 시 대체 저장 설명, 삭제 결과 확인 부족 |
| ../lib/db.js | users·sessions·decks·class_sessions·session_items, 사진 표, 서버 시작 시 자동 적용 |

저장소의 설명과 코드를 확인한 것이며 운영 DB의 실제 내용, 실제 학생 로그인, 카메라, 다기기 동작을 시험한 것은 아니다. 과거 문서에 적힌 테스트 통과 수를 이번 작업의 테스트 결과로 재사용하지 않는다.

## 1. 전체 구조와 구현 경계

광장은 조향사 전용 앱이 아니라 공예 프로그램이 함께 사용하는 수업 기능이다. 공통 기능은 입장, 진행, 가게, 사진, 방문, 요청·답장·반응, 성찰, 저장이다. 직업별 차이는 버전이 붙은 프로그램 카드로 제공한다.

| 기존 자산 | 광장에서 사용하는 방법 |
|---|---|
| 강사 로그인과 수업 | 기존 계정·담당 수업을 그대로 사용한다. 광장용 공용 비밀번호를 만들지 않는다. |
| 자료와 수업 배정 | 실제 decks 자료로 '조향사 광장'을 등록하고 기존 session_items에 배정한다. |
| 코드 입장과 시간 제한 | 기존 검사를 통과한 접속에 광장 참여자 연결을 추가한다. 코드를 아는 것만으로 개인 기록을 열지 않는다. |
| 진로기록 | 기존 source·program_ref·session_ref·학생 번호·attempt_id 규격으로 최종 기록을 넣는다. |
| 관찰 기록·기존 사진 | 기존 기능은 유지한다. 광장 사진을 학교 관찰 사진 표에 억지로 넣지 않는다. |

권장 학생 경로는 /class#/plaza/<광장번호>, 강사 경로는 /class#/plaza-teacher/<광장번호>이며 모두 제안 명칭이다. 기존 SPA와 Node 서버 안에서 구현한다. 업로드 HTML iframe으로 광장을 실행하지 않고, allow-same-origin을 추가하지 않는다. 새 프레임워크나 라이브러리를 전제로 하지 않는다.

자료 등록은 기존 자료 생성·공개·배정 절차를 유지한다. 새 표의 deck_id 연결로 광장 자료임을 식별하고, 서버가 이 연결과 권한을 확인한 뒤 자체 화면으로 연다. 초기에는 기존 link 자료 형식을 이용하는 방향을 검토하되, 실제 뷰어의 내부 경로 처리까지 1단계에서 확인한다. 이름이나 URL 문자열만 보고 광장으로 판정하거나 새로운 decks.kind를 조용히 추가하지 않는다.

교사용 슬라이드는 학생 광장 자료와 별도로 연결한 비공개 강사용 자료로 둔다. 자세한 보호 방식은 12절에 있다.

## 2. 참여자·기기·가게·기록을 연결하는 방법

### 2.1 연결의 중심은 '이번 수업 참여자'다

수업(class_sessions) → 광장 → 참여자 → 가게·초안·사진·교류·최종 저장 접수번호로 이어진다. 접속 기기는 참여자를 찾아가는 수단이며 참여자 그 자체가 아니다.

| 연결값 | 의미와 사용 범위 |
|---|---|
| class_session_id / deck_id | 기존 수업과 실제 배정 자료. 서버가 확인한다. |
| room_id | 이번 수업에서 여는 광장 번호. 다음 수업에 재사용하지 않는다. |
| participant_id | 서버가 만든 무작위 참여자 번호. 기기가 바뀌어도 유지된다. |
| seat_label / seat_order | 강사가 찾고 촬영하는 표시와 순서. 인증 수단이 아니다. |
| store_public_id | 광장 화면에서 가게를 구분하는 불투명한 번호. 학생 번호와 다른 값이다. |
| student_uuid | 기존 서버 인증으로 확인한 진로기록 학생 번호. 서버 전용이다. 기록하지 않는 참여에서는 비워 둔다. |
| device_grant | 이번 참여자에게 발급한 현재 접속 권한. 기기 교체·종료 시 폐기한다. |
| photo_id / record_id | 사진과 최종 진로기록 접수번호. 사진은 record_id 생성 전에도 참여자에 연결할 수 있다. |

브라우저가 보낸 학생 번호, 사진 경로, 담당 강사 번호를 신뢰하지 않는다. 학교 계정으로 접속한 경우 기존 career_student_id를 그대로 사용하며 별도 학생 번호를 만들지 않는다. 코드 학생도 기존 서버가 발급한 진로기록 번호를 유지한다. 이름·자리·기기 지문·URL로 학생 번호를 만들지 않는다.

### 2.2 첫 입장과 재입장

첫 시범은 코드 입장을 중심으로 한다. 같은 수업의 유효한 로그인, 자료 배정·공개·잠금 상태, 학생 접근 시간을 통과한 후 참여자를 만든다. 자리 충돌은 서버에서 막고 강사에게 확인하도록 한다. 이미 앉은 학생의 이름·비밀정보를 충돌 메시지로 보여주지 않는다.

신규 학생 입장과 현재 참여자의 재입장을 구분한다. 현재 유효한 접속 권한이 있고 같은 수업에 속하면 저장된 가게로 복귀한다. 쿠키가 남았다는 이유만으로 다른 수업이나 다른 학생의 가게를 이어주지 않는다. 이전 수업의 가게를 입장 화면에 미리 노출하지 않는다.

기존 career-log/start는 이미 활성 식별자가 있으면 먼저 반환하고, 게스트 resume 쿠키는 90일 남는다. 따라서 광장 신규 입장은 단순히 start의 mode만 new로 보내서 해결하지 않는다. 이전 광장 연결과 로그인 상태를 정리한 신규 입장인지 서버가 먼저 확인하도록 연결 서비스를 설계한다.

진로기록을 남기지 않는 모드는 참여 전에 결정한다. 이 모드에서는 광장 참여자만 만들고 career-log/start나 career_log.students/records 생성으로 연결하지 않는다. 학교 계정이 이미 존재하더라도 새 장기 기록을 추가하지 않는다. 이 모드의 실제 수업 사용은 4단계 개인정보 관문 이후다.

### 2.3 기기를 바꾸는 경우

권장 절차는 '강사가 해당 참여자 선택 → 재발급 확인 → 이전 접속 폐기 → 새 기기에서 일회성 연결값 입력 → 같은 참여자로 복귀'다. 자리 번호만 입력해서 복구하지 않는다. QR 진로 카드는 이 단계에 넣지 않는다.

접속 비밀값은 서버에서 충분한 무작위 값으로 만들고 DB에는 해시만 둔다. 일회성 교체값은 짧게 만료하며 사용 직후 폐기한다. 예시 목표는 5분 이내, 실제 값은 시험에서 확정한다. 입력 횟수 제한과 강사 재발급 이력을 둔다. URL·접속 로그·AI 요청에 비밀값을 넣지 않는다.

활성 기기 권한은 참여자당 하나만 둔다. 재발급은 한 트랜잭션으로 기존 권한 폐기와 새 권한 발급을 처리한다. 이전 기기의 아직 진행 중인 저장은 접속 버전이 바뀌었으면 거절한다. 서버 응답을 잃고 재시도한 교체 작업도 같은 요청 번호로 확인한다.

기존 일반 진로기록 경로로 우회해서 이전 기기가 살아남으면 안 된다. 코드 학생의 기기 변경 시 기존 게스트 로그인 토큰도 폐기하고, 게스트 식별 연결값을 새 값으로 회전하여 같은 student_uuid를 새 접속으로 잇는 방향을 제안한다. 이는 aiapp의 게스트 인증 연결 로직 보완이며 공통 계정 규칙 변경이 아니다. career_log.job_identities의 연결값 갱신 범위와 기존 identity 함수 재사용 방식은 1단계에서 검증한다. career_log.records는 건드리지 않는다. 학교 계정 비밀번호나 moakit_accounts 세션 규칙은 변경하지 않는다.

### 2.4 종료와 다음 학생

최종 종료는 광장 접근 버전을 바꾸고 모든 광장 접속 권한을 폐기한다. 이번 코드 수업의 게스트 로그인·이어가기 연결도 무효화하여 기존 진로기록 API를 통한 재접근을 막는다. 클라이언트는 광장 초안 캐시, 이미지 객체, 임시 토큰을 비운다. 다른 학원의 정상 계정이나 강사의 다른 수업 세션까지 지우지 않는다.

꺼져 있던 기기는 서버 명령을 즉시 받을 수 없다. 따라서 종료 후 모든 새 요청을 서버에서 거절하고, 재접속·뒤로 가기·화면 복귀 시 권한을 확인하기 전에는 개인 내용을 그리지 않는다. 이미 내려받은 화면·스크린샷을 서버가 회수할 수 있다는 보장은 하지 않는다.

## 3. 수업 상태와 개인 완료 상태

수업 전체의 진행 위치와 학생 개인의 완료 여부는 서로 다른 값으로 관리한다.

| 수업 상태 | 화면과 가능한 일 | 넘어가는 조건 |
|---|---|---|
| 준비 | 강사가 자료·키트 카드·시간·자리 수를 확인한다. 학생 활동은 시작하지 않는다. | 수업과 카드 준비 완료 후 강사가 시작 |
| 진행: 구상 | 입장, 손님, 시향지·재료 선택, AI 구상, 수정, 이름, 간판 저장 | 강사가 미완료 수를 보고 다음 단계 선택 |
| 잠시 멈춤: 제작 | '제작하러 가기'. 가게·초안은 유지하고 강사는 촬영할 수 있다. 수업 종료가 아니다. | 기존 수업·접근 시간 안에서 강사가 재개 |
| 진행: 개장 준비 | 재입장, 실제 제작 결과 확인, 실제 참여자 확인, 순환 방문 배정 | 강사가 명단 확인 후 개장 |
| 진행: 교류 | 요청 → 받은 요청에 답장 → 답장에 반응 | 학생별 실제 제출을 따로 집계 |
| 진행: 돌아보기·저장 확인 | 돌아보기 3문항, 기록할 내용 확인, 서버 저장 접수 확인 | 강사가 저장·미완료 현황 확인 |
| 종료 | 학생 조회·쓰기·사진 접근을 막는다. 기존 가게로 신규 입장할 수 없다. | 종료 상태를 재개로 되돌리지 않는다. 다음 수업은 새 광장 |

'다음 단계'는 수업 단계만 바꾼다. 아직 구상을 저장하지 못한 학생을 완료로 바꾸지 않는다. 개인 항목은 미시작·작성 중·저장 확인 필요·서버 저장 완료·대체 진행·기록하지 않음으로 구분한다. 결석·중도 이탈은 참여 상태로 따로 둔다.

시간표는 plaza-plan.md 그대로 유지한다. 강사가 보는 타이머는 안내용이고 시간이 지났다는 이유로 학생 제출을 자동 생성하지 않는다. 제작 중 기존 class_sessions.active를 끄거나 자료를 임의로 잠그지 않는다. 수업 만료나 기존 시간표가 먼저 끝나면 광장도 이를 존중하며 정상 강사 설정에서 해결한다. 광장용 시간 제한 면제는 만들지 않는다.

최종 종료 전에는 '기록 저장 완료 / 확인 필요 / 미완료 / 기록하지 않음 / 사진 전송 중'을 나누어 보여준다. 미완료 상태에서 강사가 종료를 선택할 수는 있으나, 사유와 현황을 남기고 학생의 활동·기록을 완료로 바꾸지 않는다. 이미 종료된 뒤 학생 명의로 몰래 저장을 재시도하지 않는다.

## 4. 새 표의 제안

아래는 데이터 설계이며 실행 SQL이 아니다. 신규 표는 aiapp 전용으로 만들고 moakit_accounts의 구조·규칙을 바꾸지 않는다. 기존 career_log.records의 구조·원본도 바꾸지 않는다. 표 이름과 세부 분리는 1단계 설계 검증에서 조정할 수 있으나 권한 경계와 데이터 보존 원칙은 유지한다.

| 제안 표 | 보관할 것 | 핵심 제한 |
|---|---|---|

## 5. 권한과 조회 범위

### 5.1 공통 검사

광장 API는 기존 lib/api.js의 로그인·역할·동의·접근 시간 검사를 통과한 후 추가로 광장과 참여자 소유권을 검사한다. 학생은 기존 자료 배정·공개·잠금 규칙도 통과해야 한다. 접근을 통과하지 못하면 빈 화면으로 숨기는 데 그치지 않고 서버에서 거절한다. 쓰기는 기존 sameOrigin 방식과 같은 출처 검사를 적용한다.

새 표는 서버 전용을 기본으로 한다. 공개 API에 노출되는 스키마에 두는 경우에도 RLS를 켜고 PUBLIC·anon·authenticated의 직접 접근을 회수한다. 브라우저가 DB나 Storage 관리 키를 갖지 않는다. aiapp은 자체 로그인과 Postgres 연결을 쓰므로 Supabase auth.uid()만으로 학생을 판정하는 정책을 복사하지 않는다. 서버의 DB 권한이 RLS를 우회할 수 있으므로 API의 수업·학생 검사도 반드시 필요하다.

| 이용자 | 볼 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| 미로그인·수업 코드만 아는 사람 | 일반 입장 안내 | 광장 전시·개인 활동·사진·교안 조회 |
| 이번 수업의 유효한 학생 | 같은 광장의 승인된 전시 항목, 자신의 초안, 자신이 당사자인 요청·답장·반응 | 타인 성찰·학생 연결값·전체 교류 원문·타인 초안 조회 |
| 담당 강사 | 담당 수업의 자리·가게·단계·저장 상태, 촬영·재배정 도구, 강사 자료 | 다른 수업 관리, 학생의 성찰을 대신 제출, 기존 학교 기록 권한 확대 |
| 관리자 | 기존 관리자 권한 안의 관리 기능 | 승인 없는 운영 시험·학생 기록 생성 |
| 진로업체 담당자(partner) | 기존에 허용된 학생 기록 기능 | 기본안에서는 광장 진행·촬영·교안 접근 불가. 역할 서열만으로 열지 않음 |

첫 시범 현장 운영은 담당 instructor 계정으로 통일하는 것을 권장한다. partner에게 광장 운영까지 허용해야 하면 사용자의 별도 결정 후 필요한 경로만 검토한다. PARTNER_ALLOW나 역할 서열을 일괄 확대하지 않는다.

### 5.2 '광장 공개'는 인터넷 공개가 아니다

전시 조회는 이번 수업의 인증된 참여자에게만 제공한다. 허용 항목은 가게 이름, 전시 그림, 전시 사진, 학생이 고른 소개 문구와 화면에 필요한 전시 상태다. 내부 라우팅용 가게 식별자는 포함할 수 있지만 학생 번호·자리·학교·로그인 식별자·기록 번호로 역추적할 수 없게 분리한다.

개인 초안과 성찰은 본인용 조회, 요청·답장·반응은 당사자용 조회, 진행 현황은 강사용 조회로 나눈다. 기존 /api/career-log/records를 광장 전체 조회로 재사용하지 않는다. 전시 조회에 records나 초안의 원문을 통째로 붙이지 않는다. 타 수업의 가게·사진 번호를 넣어도 권한이 넓어지지 않아야 한다.

학교 계정의 저장된 기록 열람은 기존 record_access를 따른다. 코드 학생은 기존 학교 명단 기반 담당자 조회에 아직 연결되지 않는다. 담임의 사후 확인을 새로 제공하려면 권한·제공 범위를 4단계에서 결정해야 하며, 현재 이미 가능한 기능으로 설명하지 않는다.

## 6. 촬영·사진 저장·접근 차단·파기

### 6.1 연속 촬영

강사는 자리 순서의 가게 목록에서 작품만 촬영한다. 카메라 화면은 aiapp 자체 화면이며 기기 권한을 정상 요청한다. 얼굴·학생 이름·명찰이 프레임에 들어오지 않도록 안내한다.

촬영 버튼을 누르는 순간 capture_id와 대상 참여자·가게·연결 버전을 고정한다. 화면이 다음 학생으로 넘어가도 업로드 대상은 바뀌지 않는다. 찍은 사진은 해당 가게의 전송 대기 항목이 되며 다음 자리로 이동한다. 건너뛰기, 다시 찍기, 실패 목록, 대상 수정 기능을 둔다.

| 사진 상태 | 강사가 보는 뜻 |
|---|---|
| 촬영됨 | 기기에서 촬영을 마쳤다. 아직 서버 저장을 보장하지 않는다. |
| 전송 중 | 파일과 대상 연결을 서버에서 처리 중이다. |
| 서버 저장 완료 | 파일 존재·형식·크기·소유 대상·전시본 연결을 서버가 확인했다. |
| 저장 확인 필요 | 응답이 끊겨 성공 여부를 확인해야 한다. 같은 촬영 번호로 조회·재시도한다. |
| 재시도 필요 / 재촬영 필요 | 파일 전송 실패 또는 기기에 남은 사진이 없어 다시 찍어야 한다. |

기본 촬영 큐는 기기 메모리에만 둔다. 서버에는 촬영 시도와 상태를 남긴다. 화면 종료·브라우저 재시작까지 미전송 사진을 보존한다고 약속하지 않는다. 기기 메모리가 사라진 항목은 '재촬영 필요'로 남긴다. 강사 기기의 한시적 IndexedDB 보관이 필요하면 보관기한·용량·삭제 절차를 추가 승인받는다. 학생 기기의 장기 localStorage에는 개인 활동이나 사진을 보관하지 않는다.

다시 찍을 때는 새 capture_id를 쓰되 이전 전시본을 새 사진의 서버 저장 확인 전까지 유지한다. 사진 옮기기는 같은 수업 안에서 담당 강사가 원래 가게·새 가게를 확인한 뒤 처리한다. 기존 전시를 먼저 숨기고 연결 버전을 바꾼다. 업로드 완료 직전에 대상 이동이 있었다면 이전 버전의 완료 요청을 그대로 반영하지 않는다. 옮김·재촬영 이력과 이전 파일도 파기 목록에 남긴다.

사진이 없어도 방문 배정에서 제외하지 않는다. 구상 그림과 '작품 사진 준비 중'을 표시한다. 구상 그림은 실제 작품 사진으로 기록하지 않는다. 사진 처리와 학생 진로기록 최종 저장은 서로 막지 않는다.

### 6.2 저장 위치

광장 전용 비공개 Storage 버킷을 권장한다. 기존 media 버킷이나 career_record_photos의 base64 저장을 기본 대체 경로로 쓰지 않는다. 광장 저장소가 미설정이면 촬영 기능을 '설정 필요'로 막고 구상 그림으로 진행한다. 자동 버킷 생성이나 운영 버킷 재사용은 하지 않는다.

DB에는 파일 식별자·소유권·검증 결과·보관기한만 두고 이미지 바이트는 저장소에 둔다. 파일 경로에는 학생 이름·학교·자리·학생 번호를 넣지 않는다. 무작위 파일 번호를 사용하며 버킷·경로는 서버가 정한다.

초기 사진은 브라우저에서 크기를 줄인 JPEG 중심으로 장당 한 요청씩 처리하는 안을 권장한다. 기존 제한을 참고해 긴 변 1280px과 충분히 작은 본문을 목표로 잡되 실제 상한은 시험으로 확정한다. 파일 확장자만 믿지 않고 서버에서 형식·실제 바이트·크기를 검사한다. 촬영 이미지 재생성으로 위치 등 메타데이터를 제외하고 실제 기기에서 확인한다. 더 강한 재인코딩에 새 라이브러리가 필요하면 먼저 승인을 받는다.

사진 업로드도 서버의 강사 인증을 거치는 방식을 우선한다. 직접 서명 업로드가 성능상 필요하면 별도 검토하며, 업로드 주소의 실제 유효기간과 재사용 가능성을 확인한다. 종료 후 도착한 업로드는 전시본으로 연결하지 않고 임시본 정리 대상으로 둔다.

### 6.3 짧은 링크와 수업 종료 차단

기존 lib/storage.js의 기본 다운로드 링크는 3시간이다. 이를 광장에 그대로 적용하지 않는다. 짧은 링크의 제안값은 60초이지만, 수업을 닫았다고 이미 발급된 Storage 서명 링크가 즉시 무효가 되는 것은 아니다. 따라서 학생에게 Storage 원본 서명 URL을 직접 전달하거나 302로 보내는 방식은 기본안에서 제외한다.

학생은 aiapp의 사진 조회 주소만 사용한다. 필요한 경우 이 주소의 단기 표식도 로그인·광장·접속 버전과 함께 검사한다. 서버가 요청마다 기존 시간·자료 권한, 참여자, 광장 종료·전시 상태를 확인하고 비공개 파일을 읽어 전달한다. 내부적으로 짧은 Storage 링크를 사용하더라도 브라우저와 로그에 노출하지 않는다. 학생 사진 응답은 private, no-store이며 공유 CDN 캐시에 저장하지 않는다.

종료·기기 재발급·사진 이동 시 접근 버전을 바꾸어 같은 사진 주소로 새로 요청해도 차단한다. 학생의 열린 화면은 권한 만료 시 비우고, 화면 복귀 때 서버 확인을 먼저 한다. 오프라인 기기의 이미 표시된 이미지나 개인이 찍은 스크린샷까지 삭제할 수 있다는 뜻은 아니다.

### 6.4 실제 파기

각 촬영에 원본, 썸네일, 다시 찍은 이전 파일, 임시 업로드, 고아 파일이 연결되게 한다. 파기 작업은 먼저 접근을 막고 파일별 삭제를 요청한 뒤, 실제로 없어졌는지 확인하여 완료 처리한다. 실패한 파일이 하나라도 있으면 재시도·관리자 확인 대상으로 남긴다. DB의 사진 행만 지우고 파일을 남겨두지 않는다.

기존 removeObject는 HTTP 실패 상태와 삭제 완료를 확실히 보고하지 않으므로 파기 근거로 그대로 사용할 수 없다. 광장 파기에는 파일별 응답 검증과 재조회, 최소한의 삭제 결과 기록이 필요하다. 다른 프로그램의 파일을 경로 접두어만으로 대량 삭제하지 않는다.

보관 기간은 아직 정하지 않았다. 임시본, 전시 사진, 초안, 장기 진로기록, 운영 로그, 백업을 각각 정한다. 백업·내보내기·저장소 복사본의 실제 보존·삭제 정책도 확인한다. 복원 시 삭제 대상이 다시 살아나지 않도록 삭제 목록을 재적용하는 절차를 포함한다. 백업 삭제를 확인하지 못했다면 '전체 파기 완료'라고 표시하지 않는다.

중요한 미결정: career_log.records의 UPDATE/DELETE 금지와 개인 기록 원본의 보관 종료 후 실제 파기는 현재 범위만으로 동시에 해결되지 않는다. 광장 코드에서 보호 트리거를 풀거나 우회 삭제하지 않는다. 기록 보관·파기를 담당할 기존 시스템 차원의 절차를 별도로 승인·검증하기 전에는 실제 학생 장기 기록 수집 관문을 통과시키지 않는다. 단순 숨김이나 학생 연결 삭제만으로 원문 전체 파기를 완료했다고 주장하지 않는다.

## 7. 진로기록 저장 시점과 형식

### 7.1 중간 저장과 최종 기록을 구분한다

1교시 구상·AI 제안·선택·학생 수정·간판, 3교시 실제 제작 확인과 교류 과정은 광장 표에 저장한다. 1교시에 간판이 등장했을 때의 '저장됨'은 '구상 저장됨'이며 진로기록 최종 발행과 다르다.

3교시 돌아보기 뒤 학생이 내용을 확인하고 저장하면, 확정된 활동과 성찰을 기존 진로기록 한 건으로 남기는 안을 권장한다. 기존 submission이 process와 reflection을 필수로 요구하므로 돌아보기 전에는 임의 문장을 채워 진로기록을 만들지 않는다.

| 기존 저장 항목 | 광장의 저장 방식 |
|---|---|
| source | 기존처럼 job |
| student_id | 현재 유효한 서버 인증과 참여자 연결로 확인한 번호. 클라이언트 값은 사용하지 않음 |
| program_ref | job-deck:<실제 조향사 광장 자료 ID> |
| session_ref | 코드 수업에서는 job-class:<실제 수업 ID> |
| source_event_id | 기존 job:<학생 UUID>:<attempt_id> 규격과 잠금 방식 유지 |
| process | 손님 문제, 선택한 재료·구상, 학생이 바꾼 것, 실제 제작 변경, 교류에서 한 일. 1500자 이내 |
| artifact | 작품명·가게명·학생이 확정한 소개와 제작 결과 설명. 1500자 이내 |
| reflection | 세 문항의 학생 응답을 질문과 구분하여 합친 내용. 1000자 이내 |
| raw_data.job | 기존 deck_id·제목·수업·담당 강사·identity·student_reflection 의미 유지 |
| raw_data.job.plaza | 서버가 구성한 카드 버전, 활동별 체험 전·체험·성찰, 검증된 AI 제안 출처, 학생 선택·수정, 대체 진행 구분 |
| verification_status / verified_by / verified_at | 기존처럼 null. 강사의 참여·제작 사실 확인을 내용 검증 완료로 바꾸지 않음 |

기존 계정 자료의 job-account-deck 규격도 바꾸지 않는다. 첫 시범은 코드 수업이므로 job-class 규격을 쓰며, 계정 입장까지 이번 수업에 연계하려면 실제 class context를 서버가 확인하는 방법을 별도 검증한다. 클라이언트가 보낸 수업 번호로 형식을 강제로 바꾸지 않는다.

학생 화면의 기존 3칸만 보아도 AI가 제안한 내용과 학생이 결정한 내용이 구별되도록 문구를 구성한다. 추가 세부 데이터가 보이지 않는 모아허브에서도 의미가 뒤집히지 않게 한다. 새 program_ref 접두어, 관찰 기록 종류, 기존 공통 표시 규칙은 만들거나 바꾸지 않는다.

확정 기록에는 다른 학생의 원문 성찰·식별자·전체 답장을 복제하지 않는다. 사진 바이트·다운로드 URL도 넣지 않는다. 사진은 외부 연결 표에서 관리해 전시본 수정이나 파일 파기가 진로기록 원문 수정을 요구하지 않게 한다.

### 7.2 한 번만 저장하기

최종 제출 때 attempt_id를 한 번 만들고 제출 내용을 고정한다. 새로고침·기기 변경·응답 유실·재시도에도 같은 번호를 사용한다. 같은 번호·같은 내용은 기존 접수번호를 반환하고 같은 번호·다른 내용은 409로 알린다. 무작정 새 번호를 발급해 같은 기록을 여러 건 만들지 않는다.

현재 학생 저장 함수는 광장 상태나 추가 provenance 데이터를 받는 전용 기능이 없다. 다음 단계에서 기존 인증·검증·삽입을 재사용하는 내부 저장 서비스를 검토하고, 광장 서버가 확정 데이터로 호출하도록 설계한다. 학생이 보낸 raw_data를 그대로 records에 넣는 일반 통로는 만들지 않는다.

광장 최종 접수와 career_log INSERT는 가능하면 같은 트랜잭션에서 처리한다. 기존 attempt_id 잠금에 더해 참여자·수업·자료별 최종 제출 하나를 보장한다. 광장 추가 데이터까지 포함한 고정 내용 해시도 비교하여 글 3칸이 같다는 이유로 다른 활동 출처를 덮어씌우지 않는다. 수업 종료와 최종 저장이 겹치면 같은 수업 상태 잠금 안에서 순서를 정하고 저장 직전 접근을 다시 검사한다.

네트워크 응답만 사라졌으면 '저장 확인 필요'다. 401·시간 차단·자료 차단은 자동 재시도하지 않는다. 수업 종료 뒤 미완료 학생의 내용을 강사가 학생 명의로 대리 확정하지 않는다. 이미 저장된 기록의 정정은 기존 권한·supersedes_id 절차를 따른다.

### 7.3 사실 표시와 기록하지 않는 학생

강사는 참여·제작 사실만 별도로 표시한다. 이 표시는 학생이 어떤 생각을 했는지, AI를 실제로 썼는지, 성찰을 완료했는지 대신 증명하지 않는다. 담임의 내용 확인은 별도 단계이며 자동 검증 표시를 넣지 않는다.

기록하지 않음을 선택한 학생도 가게와 교류에는 참여할 수 있게 설계하되, 장기 진로기록·최종 저장 접수 생성은 하지 않는다. 전시 사진 참여 여부는 별도 선택으로 다룬다. 직접 기존 기록 API를 호출해도 광장 자료의 기록 거부를 우회할 수 없도록 광장 자료에 한정한 정책 검사 지점을 둔다. 임시 수업 처리 자체의 적법한 근거까지 불필요하다는 뜻은 아니며 실제 운영 전 확인이 필요하다.

## 8. 프로그램 카드 데이터 구조

카드는 데이터이며 임의 HTML·실행 스크립트·학생이 수정하는 시스템 프롬프트를 허용하지 않는다. 수업을 열면 검토된 카드 버전을 고정하고 중간에 카드 내용이 바뀌어도 진행 중 수업에는 자동 반영하지 않는다.

| 카드 묶음 | 포함할 항목 |
|---|---|
| 식별 | program_key, version, 직업명, 결과물명, 연결 deck_id, 검토 상태 |
| 문제·손님 | 문제 문장, 손님 카드 id·제목·설명·그림 참조 |
| 재료 | 키트 재료 id·이름·그림·한 줄 설명, 시향지 표시, 강사 검토자·검토일 |
| 허용 조합 | 강사가 확인한 조합 id·재료 목록, 학생이 바꿀 수 있는 범위, 제작 안내 참조 |
| AI 규칙 | 구상 2개, 사용 가능한 재료·조합·설명, 금지 표현, 출력 길이·형식, 답장 초안 1회 |
| 요청 | 제작 뒤에도 답할 수 있는 요청 카드 id·문장, 사용할 수 있는 확인된 사용 안내 |
| 이름·간판 | 작품·가게 이름 후보, 간판 배치 종류, 소개 문구 선택지 |
| 학년별 입력 | 저학년 선택형·문장 시작말, 중등 짧은 수정형, 입력 길이, 도움말 |
| 예시 | AI 실패 때 쓰는 검토된 구상·답장 예시, 예시 버전과 출처 표시 |
| 교안·이미지 | 비공개 강사 교안 자료 id, 허용된 그림 참조, 권리 확인 정보 |

공통 수업 순서는 카드가 임의로 바꾸지 못한다. 직업마다 인증·사진·방문 코드를 복사하는 방식으로 확장하지 않는다. 첫 카드의 program_key 제안은 perfumer-gypsum이다.

첫 카드의 문제, 손님 3종, 요청 3종은 plaza-plan.md의 문구를 그대로 사용한다. 효능·치료·감정 진단은 하지 않고 비율·사용량은 키트 안내를 따른다. 재료는 아직 받지 않았으므로 실제 향 이름이나 조합을 임의로 채우지 않는다. 카드의 실제 수업 활성 상태는 '키트 목록 확인 대기'로 둔다. 개발용 가짜 재료는 시험 데이터에만 두고 실제 재료로 설명하지 않는다.

학생은 책상의 시향지를 맡으며 재료를 고른다. AI가 제안하는 두 안은 검토된 조합 안에서만 달라져야 한다. 학생의 '한 가지 바꾸기'는 허용된 재료 교체나 설명·소개 선택 변경 등 명시한 범위로 제한하며, 아무것도 달라지지 않은 제출을 수정 완료로 표시하지 않는다. 허용 조합이 부족하면 AI가 새 조합을 발명하는 대신 강사 확인 대상으로 둔다.

## 9. 방문·요청·답장·반응

개장 직전에 강사가 실제 참여자를 확정한다. 단순히 최근 통신이 없다는 이유만으로 제작 중인 학생을 결석 처리하지 않는다. 사진이 없는 학생도 참여자 명단에 포함한다.

2명 이상이면 무작위로 순서를 정한 뒤 순환 배정한다. 예를 들어 A→B→C→A이면 각 학생은 한 곳을 방문하고 한 명의 손님을 받는다. 홀수도 같은 방식이다. 배정은 서버 트랜잭션으로 한 번 확정하고 새로고침 때마다 다시 뽑지 않는다. 자기 가게 방문은 금지한다.

| 상황 | 처리 |
|---|---|
| 아직 요청 전 결석 확인 | 영향을 받는 미진행 배정만 강사가 수리한다. 변경 이력을 남긴다. |
| 요청을 보낸 뒤 상대 이탈 | 이미 보낸 요청과 상대를 보존한다. 강사·예시 대체는 별도 주체와 사유를 붙인다. |
| 늦게 복귀한 학생 | 기존 배정을 먼저 확인한다. 완료된 교류를 취소하거나 새 손님으로 전체를 다시 섞지 않는다. |
| 1명만 참여 | 강사 또는 예시 손님으로 대체하고 학생 간 교류 완료로 집계하지 않는다. |
| 참여자 0명 | 개장하지 않는다. 오류가 아니라 강사 확인 상태로 둔다. |

요청 1개 보내기, 받은 요청 1개 답하기, 자신이 받은 답장에 반응 1개를 각각 추적한다. 주고받은 메시지는 전송 후 확정본으로 관리하며 중복 클릭·재전송에도 하나만 생기게 한다. 반응은 '설명이 이해됐어요', '이 부분이 궁금해요' 등의 선택형이고 별점·좋아요·인기 순위는 만들지 않는다.

대체 진행은 단계별로 누가 무엇을 대신했는지 구분한다. 예시 답장을 읽었다는 사실을 학생이 AI로 답한 것으로 만들지 않고, 강사가 보낸 반응을 학생 반응으로 만들지 않는다. 강사의 현황에는 실제 또래 교류 완결과 대체 진행 완결을 별도로 표시한다.

## 10. AI 호출과 장애 대응

학생 브라우저는 외부 AI를 직접 호출하지 않는다. 서버는 수업·자료·참여자·단계·요청 횟수를 확인한 뒤 호출한다. AI 제공사·모델·키·비용 상한은 아직 정하지 않았고 승인 전에 임의로 유료 서비스를 선택하지 않는다.

외부 입력은 가상 손님 카드, 강사가 검토한 재료·허용 조합·사용 안내, 학생의 선택형 값만 포함한다. 학생 번호, 이름, 학교, 자리, 가게명 자유 입력, 작품 사진, 성찰, 수정한 자유 서술 답장, 다른 학생 정보는 보내지 않는다. 개인정보 제거가 성공할 것이라고 가정하여 자유 글 전체를 전송하지 않는다.

AI는 구상 단계에서 한 번에 2개 안을 내고, 답장 단계에서 초안을 1번 낸다. 반복 클릭이나 통신 재시도로 새 호출을 계속 만들지 않는다. 외부 응답은 허용 재료·조합·길이·금지 표현을 서버에서 검증한다. 기준에 맞지 않는 출력은 학생에게 바로 보이지 않고 준비된 예시로 대체한다. 실제 키트 안내와 충돌하는 사용량·효능 설명은 허용하지 않는다.

| 구분 | 기록할 사실 |
|---|---|
| AI 결과 사용 | 검증된 AI 제안, 학생이 고른 안, 학생이 바꾼 것 |
| 준비된 예시 사용 | 예시 버전과 학생 선택·수정. AI 결과를 사용한 활동으로 집계하지 않음 |
| 강사 도움 | 어떤 단계에서 강사가 도왔는지 |
| 종이 진행 | 인터넷 장애로 종이에 요청·답장·반응을 했는지 |

실제 AI 호출이 있었지만 실패해서 예시를 쓴 경우, 비용·호출 로그에는 호출 사실을 남기되 학생의 활동 출처는 예시로 남긴다. 호출 여부와 학생이 실제 사용한 결과를 한 값으로 합치지 않는다.

AI만 멈추면 준비된 예시로 진행하고, 인터넷이 끊기면 종이 요청 카드로 진행한다. 인터넷 없이 서버 저장 완료라고 표시하지 않는다. 연결이 돌아와도 학생 본인이 확인한 내용만 정상 권한 안에서 저장한다. 강사가 나중에 옮긴 종이 기록을 학생 직접 작성으로 위장하지 않는다. 코드 학생의 사후 대리 기록 경로는 현재 없으므로 4단계에서 별도 결정한다.

## 11. 화면 갱신·시간 운영·저장 표시

광장 그림은 한 화면 마을형이다. 간판 글자, 상태, 버튼, 입력칸은 실제 화면 요소로 둔다. 가게가 많은 태블릿에서는 전체 위치를 유지하면서 '내 가게'·'방문할 가게'를 크게 열 수 있게 한다. 그림만 눌러야 하는 방식 대신 키보드·터치로 접근할 수 있는 목록도 제공한다.

갱신 주기는 화면이 보일 때 약 3초를 초기 제안으로 하며 시험 후 조정한다. 전체 페이지나 입력 폼을 다시 그리지 않고 변경된 가게·전시·배정·본인 요청 상태만 갱신한다. 서버는 수업 단위 변경 버전을 사용하고 학생 권한에 맞게 결과를 추린다. 순서가 뒤바뀐 응답이나 오래된 저장 응답이 새 글을 덮어쓰지 않도록 한다. 한글 조합 입력·커서·선택 영역을 보존한다.

기존 앱에는 5분마다 refreshMe → navigate로 화면이 다시 만들어지는 제약이 문서화되어 있다. 광장에서는 로그인·권한 재검사는 유지하되 인증 상태가 그대로인 주기 갱신이 입력 중인 광장 화면을 재생성하지 않도록 통합 지점을 검토한다. 기존 뷰어 전체를 관계없이 개편하지 않는다.

초안은 입력 후 서버에 버전과 함께 저장한다. '저장 중', '구상 저장됨', '저장 확인 필요', '진로기록 저장 완료'를 구분한다. 서버가 해당 버전의 저장을 확인했을 때만 완료로 표시한다. 버전 충돌은 사용자의 입력을 보존하고 알려 주며 자동 덮어쓰지 않는다.

이름은 후보를 고른 뒤 수정하게 하고 간판은 자동 배치한다. 첫 시범에는 꾸미기 메뉴를 늘리지 않는다. 자유 입력의 길이를 제한하고 HTML이 아닌 글자로 출력하며 이름·연락처 등 개인정보 입력을 안내·제한한다. 학생에게 공개되는 문구는 선택형 중심으로 구성한다.

모든 한글 UI는 에스코어드림, word-break: keep-all, 충분한 줄 높이를 사용한다. 강제 줄바꿈과 이모지는 사용하지 않는다. 버튼은 '제작하러 가기', '광장 열기', '요청 보내기', '다시 확인하기'처럼 행동을 말한다. AI 채팅 화면을 흉내 낸 과한 문구나 축하 메시지는 넣지 않는다.

## 12. 교사용 슬라이드 보호

직업 소개와 수업 안내 슬라이드는 앱 안에서 담당 강사가 발표한다. 학생에게 배정되는 광장 자료와 강사용 교안 자료를 분리하고, 교안 원문·발표자 설명·비공개 미디어는 일반 공개 정적 파일에 넣지 않는다. 공개 저장소의 자바스크립트·이미지 파일 안에 교안 전체를 넣으면 로그인 화면으로 가려도 원문 비공개는 보장되지 않는다.

권장안은 비공개 자료와 서버 인증 조회다. 강사 로그인과 기존 자료 사용 권한을 확인한 전용 조회에서만 교안 내용을 제공한다. 학생, partner, 미로그인, 권한 없는 강사가 URL이나 자료 번호를 직접 입력해도 거절해야 한다. student_visible=false만 믿지 않고 일반 자료·슬라이드·이미지 직접 조회 경로의 우회 가능성도 시험한다. 공개 저장소에는 공통 발표 UI만 둔다. 비밀번호나 API 키를 코드에 적지 않는다.

2단계 교안은 직업 소개 10분용 내용과 진행 안내를 포함한다. 슬라이드 문장을 만드는 작업은 이번 0단계 범위에 포함하지 않는다. 외부 이미지·영상은 실제 사용 권한과 접근 가능성을 확인한 자료만 사용한다.

## 13. 시험 환경과 단계별 관문

### 13.1 브랜치와 배포

현재 운영 기준 브랜치는 main이 아니라 claude/career-education-webapp-xem8ui다. 이번 문서는 그 기준 커밋에서 분리한 docs/plaza-stage0-20261004에만 둔다. 어느 운영 브랜치에도 합치지 않고 PR 자동 병합·운영 배포·도메인 변경을 하지 않는다.

0단계는 미리보기 배포가 필요 없다. Git 연동에 따른 자동 미리보기까지 고려해야 하며 문서 커밋이라는 이유로 자동 배포가 없을 것이라 단정하지 않는다. 저장 후 해당 커밋의 배포 상태를 확인한다. [skip ci] 같은 커밋 문구만으로 Vercel 배포 차단이 보장된다고 간주하지 않는다.

1단계 이후 미리보기는 시험용 DB와 비공개 시험 저장소가 확인된 경우에만 사용한다. 운영 프로젝트의 Preview 환경이 Production과 같은 DB를 가리킬 수도 있으므로 이름만 보고 시험 환경이라고 판단하지 않는다. 별도 시험 프로젝트나 브랜치 한정 환경변수 중 어떤 방식을 쓸지 먼저 결정한다. 새로운 저장소는 필요하지 않다.

### 13.2 DB·파일·비밀값 격리

| 항목 | 시험 환경의 조건 |
|---|---|
| DATABASE_URL | 운영과 다른 시험 DB. 운영 연결 문자열을 복사하지 않음 |
| Storage | 운영과 다른 시험 프로젝트·비공개 버킷·키. 기존 media 버킷 사용 금지 |
| 공통 계정 관련 시험 | 필요한 최소 구조를 시험 DB에 재현한 가짜 값만 사용. 운영 moakit_accounts에 연결·변경하지 않음 |
| AI | 별도 시험 키와 호출 상한. 기본 연결 시험은 AI 없이 진행 |
| 기록 데이터 | 가짜 학생·가짜 작품만 사용. 실제 학교 명단·기록·사진을 복제하지 않음 |
| 비밀값 | 환경 설정에만 보관. 문서·코드·스크린샷·저장소에 기재하지 않음 |
| 환경 확인 | 실제 연결 대상과 시험 표식을 확인한 뒤에만 쓰기 허용. 시험 여부가 불명확하면 중단 |

lib/db.js는 서버 초기화 때 자동으로 표와 기본 설정을 적용한다. 따라서 코드 작성 전부터 시험 DB 분리가 필요하다. 이번에는 자동 적용 목록을 수정하지 않는다. 1단계 이후에도 새 표를 그 목록에 넣는 것은 사용자의 별도 승인 뒤에만 한다. 먼저 검토 가능한 별도 변경안으로 제출하고, 승인된 시험 DB에서만 적용·검증한다. 운영 트랜잭션을 열었다가 ROLLBACK하는 방식으로 시험 환경을 대체하지 않는다.

### 13.3 단계별 완료 범위

| 단계 | 완료해야 하는 범위 | 종료 시 보고 |
|---|---|---|
| 0 | 요청 원문, 설계, 충돌·결정 목록, 그림 목록·프롬프트 | 문서 두 개만 저장하고 중단 |
| 1 | 코드 입장 → 구상 저장 → 잠시 멈춤 → 같은 참여자 재입장 → 강사 사진 연결 | 시험 환경 증거, 다른 학생과 섞이지 않는 연결, 기존 테스트 결과 |
| 2 | 조향사 전체 수업, 제한된 AI, 전시·교류·성찰·기록, 비공개 교안 | 전체 흐름과 저장 검증, 남은 예외 |
| 3 | 기기 변경·사진 실패·결석·중복·AI/인터넷 장애·가짜 참여자·리허설 | 다기기 재현 결과와 강사 단독 운영 기록 |
| 4 | 보관·파기 실행 검증, 기록 거부 경로, 학교 제출 처리 흐름·책임 정리 | 실제 학생 기록을 받을 조건 충족 여부. 운영은 별도 승인 전 금지 |
| 5 | 시범 피드백 반영, QR 진로 카드, 다른 카드 | 별도 사용자 요청 범위만 진행 |

권한 거절·중복 저장·버전 충돌의 기본 구조는 1단계부터 넣고, 이를 실제 장애로 재현하는 종합 시험을 3단계에 한다. 보안을 3단계까지 미룬다는 뜻이 아니다.

향 목록, 시범 학교의 기기·수업 일정, 협력사 강사비와 기기·인쇄 담당은 미확정이다. 미확정 값을 실제 운영 준비 완료로 표시하지 않는다.

| D8. 사진·초안·기록·백업 보관 기간 | 종류별 기간, 삭제 책임자, 실패 대응, 실제 원본 기록 파기 경로를 각각 정함 | 실제 학생 기록 전 |
| D9. 기록·사진을 원하지 않는 학생과 담임 확인 | 수업 참여와 장기 보관·전시를 구분하고 학교와 제공 범위 확정 | 4단계 |
| D10. 학교·협력사 책임과 운영 준비 | 처리 근거·동의·위탁/제공·외부 AI·학교 제출 서류, 강사비·기기·인쇄 담당 정리 | 실제 학교 시범 전 |

0단계 문서 확인은 SQL 적용이나 운영 배포 승인으로 해석하지 않는다. 모든 다음 단계는 명시적인 요청 뒤에 시작한다.

## 16. 필요한 그림과 생성용 프롬프트

이번에는 그림을 생성하지 않고 목록과 프롬프트만 보관한다. 저장 경로는 향후 제안이다. 학생 작품 사진·강사용 비공개 슬라이드는 이 공개 그림 폴더에 넣지 않는다. 향기 타로 원본 앱은 수정하지 않으며 제공받고 권리를 확인한 그림·재료만 필요한 범위로 사용한다.

### 16.1 공통 스타일

과하게 귀엽거나 AI 캐릭터 같은 그림 대신 실제 모형을 촬영한 듯한 작은 공방 거리로 통일한다. 밝은 아이보리·자연스러운 재료색·절제된 모아킷 티일을 사용한다. 행동 강조는 화면 요소에서 처리한다. 배경과 가게는 같은 시점·조명·스케일이어야 한다. 숫자, 글자, 로고, 사람, 이모지, 버튼, 상태 표시를 이미지에 그리지 않는다.

| 그림 | 향후 경로 제안 | 규격·역할 |
|---|---|---|
| 공방 광장 배경 1장 | public/brand/plaza/plaza-background.webp | 16:9, 원본 2560×1440 권장. 길·광장만 두고 가게 배치 영역을 넉넉히 비움 |
| 빈 가게 틀 1장 | public/brand/plaza/store-shell.png | 투명 배경 1024×1024 권장. 빈 간판, 비어 있는 전시창, 같은 기준선 |
| 빈 가게 틀의 작은 변형 1~2장 | public/brand/plaza/store-shell-b.png 등 | 선택 사항. 기본 틀과 같은 크기·간판 위치·전시창 영역. 종류를 과도하게 늘리지 않음 |

간판 전용 이미지, 불 켜진 가게 별도 이미지, 버튼 이미지, 완료 표시 이미지는 필요 없다. 간판은 빈 영역 위 실제 글자로, 불 켜짐은 화면의 조명 효과로, 상태는 텍스트로 구현한다. 사진 없는 구상 전시는 프로그램의 검토된 재료 그림과 실제 텍스트를 조합해 만들고 '구상 이미지'임을 표시한다. 학생별 AI 이미지 생성은 첫 시범의 필수 기능이 아니다.

### 16.2 광장 배경 생성용 프롬프트

> 학교 진로수업 웹앱에 사용할 작은 공방 광장의 배경 한 장. 실제 건축 모형을 정교하게 촬영한 듯한 자연스럽고 전문적인 미니어처 공간. 약간 위에서 내려다보는 고정된 정사영에 가까운 시점, 부드러운 낮의 확산광, 아이보리 바닥과 절제된 티일 포인트. 중앙에 작은 광장과 가게로 이어질 동선이 있고, 가장자리와 중앙 주변에는 웹앱이 가게를 배치할 충분히 넓고 비어 있는 영역을 남긴다. 완성된 가게나 읽을 수 있는 간판은 배경에 넣지 않는다. 여러 가게 요소를 나중에 겹쳐도 복잡해지지 않는 단순한 공간. 사람, 캐릭터, 글자, 숫자, 로고, 이모지, 버튼, UI, 워터마크 없음. 16:9 가로 화면, 2560×1440 기준. 지나치게 만화 같거나 반짝이는 3D 장난감 질감, 채도가 높은 네온색, 과장된 원근감은 피한다.

### 16.3 빈 가게 틀 생성용 프롬프트

> 앞서 승인한 광장 배경과 같은 시점과 조명으로 사용할 작은 공방 가게 한 채. 실제 나무·석고·유리로 만든 건축 모형을 촬영한 듯한 정교하고 차분한 미니어처. 아이보리 외벽, 자연스러운 밝은 나무, 절제된 티일 차양. 상단에는 웹앱이 가게 이름을 실제 글자로 얹을 넓고 완전히 빈 간판 영역, 중앙에는 작품 사진이나 구상 그림을 얹을 비어 있는 직사각형 전시 영역을 둔다. 문과 지붕은 전시 영역을 가리지 않는다. 투명 배경, 오브젝트 전체가 잘리지 않게 여백 확보, 정사각형 1024×1024. 글자, 숫자, 로고, 사람, 캐릭터, 작품, 상품명, 버튼, 상태 표시, 워터마크 없음. 과한 광택·게임 캐릭터풍·네온색은 피한다. 바닥 그림자는 약하고 자연스럽게 유지한다.

### 16.4 가게 변형 생성용 프롬프트

> 승인된 빈 가게 틀을 기준으로 지붕 모양이나 차양 소재만 조금 다르게 한 공방 한 채. 카메라 시점, 조명, 전체 크기, 바닥 기준선, 빈 간판의 위치와 크기, 전시창의 위치와 크기는 기준 이미지와 일치시킨다. 티일과 아이보리의 같은 계열을 유지한다. 투명 배경 1024×1024. 글자·사람·캐릭터·상품·숫자·UI·워터마크 없음. 화면 상태에 따른 밝기나 완료 표시를 이미지에 넣지 않는다.

생성 후에는 글자가 끼어 있지 않은지, 투명 배경이 실제 알파인지, 가게 기준선이 맞는지 확인한다. 간판·전시창의 화면 좌표는 승인된 원본에서 측정해 정하고 감으로 고정하지 않는다. 노트북·태블릿·모바일에서 글자 가독성을 별도 확인한다. 웹용 변환·압축은 원본 확인 후 한다.

## 18. 외부 확인 자료와 이번 작업의 한계

기술 동작은 구현 직전에 공식 문서를 다시 확인한다. 특히 Storage 서명 링크의 만료와 세션 종료는 같은 의미가 아니다.

- Supabase 공식 파일 제공 문서: https://supabase.com/docs/guides/storage/serving/downloads — 비공개 파일 제공과 서명 링크의 만료·인증 키와의 관계 확인.
- Supabase 공식 Smart CDN 문서: https://supabase.com/docs/guides/storage/cdn/smart-cdn — 캐시와 링크 만료를 별개로 검토할 근거. 광장 학생 사진은 공유 캐시 없이 인증 서버 경유를 제안함.
- Vercel 공식 Ignored Build Step 안내: https://vercel.com/kb/guide/how-do-i-use-the-ignored-build-step-field-on-vercel — 문서 변경도 자동 배포 설정의 영향을 받을 수 있어 별도 확인 필요.

이번 작업은 지정한 여섯 파일의 소스 검토와 설계 문서 작성이다. 실제 DB·Storage·AI 키·카메라·학생 기기를 시험하지 않았다. 로컬 실행 환경에서 저장소를 내려받는 네트워크 연결이 되지 않아 npm run check와 npm test도 실행하지 않았다. 변경 파일 비교로 문서 두 개만 추가되었는지 확인하며, 실행 테스트 통과나 시험 환경 분리 완료를 주장하지 않는다.
