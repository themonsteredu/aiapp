[지켜야 할 것]
- 모아허브(teacher-s-project), 공통 계정 규칙(moakit_accounts), 기존 향기 타로 앱은 건드리지 않는다.
- 업로드형 HTML 웹앱의 격리를 풀지 않는다. 광장과 강사 촬영 화면은 aiapp 자체 화면으로 만든다.
- 기존 진로기록 저장 규격(job-deck:<자료ID>, job-class:<수업ID>, 서버가 정하는 학생 번호, attempt_id 중복 방지)을 유지한다. "조향사 광장"은 모아랩 자료로 등록해 쓴다. career_log.records는 UPDATE/DELETE하지 않는다.
- 쓰는 중인 내용(구상, 답장 초안)은 광장 쪽 표에 두고, 확정된 활동과 돌아보기만 진로기록에 남긴다.
- 기존 권한, 학생 접근 시간, 자료 배정 규칙을 우회하지 않는다. 기존 테스트(npm run check, npm test)는 계속 통과해야 한다. 새 라이브러리나 프레임워크는 먼저 묻는다.
- 작업은 새 브랜치에서만 한다. main에 합치거나 운영 배포하지 않는다. lib/db.js 자동 적용 목록에 새 표를 넣는 건 내 승인 뒤에만. 미리보기 배포는 운영이 아닌 시험용 DB와 저장소를 쓰게 한다.
- 화면 규칙: 폰트 에스코어드림, AI스럽지 않은 자연스러운 문구, 이모지 쓰지 않기. 교사용 슬라이드는 앱 안에 넣되 강사 로그인으로만 열리게 한다(공개 저장소라 비밀번호를 코드에 적지 않는다).

[수업 루틴 - 모든 공예 프로그램 공통]
1교시 0~10분 강사: 직업 소개
1교시 10~30분 AI: 입장·자리 확인(3) → 문제·손님 카드(2) → 재료 고르기 → AI 제안 2개 → 하나 고르고 한 가지 바꾸기(7) → 작품·가게 이름(후보 고른 뒤 수정), 간판 자동 배치(3) → 광장에 간판 등장, 서버 저장 확인(2) → 늦은 학생 지원(3) → "제작하러 가기"(잠시 멈춤이며 수업 종료가 아님)
1교시 30~45분 강사: 재료 소개·시연
2교시 강사: 제작
3교시 0~20분 강사: 마무리, 강사가 작품 사진 연속 촬영
3교시 20~45분 AI: 재입장, 처음 구상대로 만들었는지 확인, 광장 개장(5) → 배정된 가게 1곳 방문해 요청 카드 보내기(6) → 받은 요청에 AI 초안 1번과 학생 수정으로 답하기(5) → 답장 읽고 반응 고르기(2) → 돌아보기 3문항(5) → 서버 저장 확인, 수업 종료(2)
돌아보기 3문항: 오늘 한 일 중 가장 기억에 남는 것 / 막혔을 때 나는 어떻게 했나 / 이 일에 대해 더 알고 싶은 것

[공통 기능 + 프로그램 카드]
광장은 조향사 전용이 아니라 공통 기능이다. 프로그램마다 아래 "프로그램 카드"만 바꿔 끼운다.
- 직업명, 문제 문장, 손님 카드, 재료 선택지(키트 기준, 그림과 한 줄 설명), AI 제안 규칙(허용 범위, 금지 표현), 요청 카드(제작 뒤에도 답할 수 있는 것), 학년별 입력 방식(저학년은 선택 위주)
첫 카드는 조향사(석고 방향제):
- 문제: 사람마다 향을 받아들이는 정도가 다르다. 서로 다른 손님을 배려하는 제품과 설명은 어떻게 만들까?
- 손님 카드 예: 강한 향이 부담스러운 손님 / 향을 말로 이해하고 싶은 손님 / 선물할 사람의 취향을 모르는 손님
- 재료: 강사가 확인한 키트 향 목록과 가능한 조합만 쓴다(목록은 따로 준다). 학생은 책상의 시향지를 맡으며 고른다.
- AI: 그 범위 안에서 구상 2개와 설명만 제안한다. 효능·치료 표현은 금지. 비율과 사용량은 키트 안내를 따른다.
- 요청 카드 예: "강한 향이 부담스러운 손님에게 어떻게 소개할까요?" / "선물 받는 사람이 처음 써도 편하려면?" / "어디에 두면 좋을까요?"

[핵심 설계 요구]
- 이번 수업 참여자, 접속 기기, 자리, 가게, 사진, 진로기록 번호가 끝까지 이어진다. 자리 번호는 표시용이지 열쇠가 아니다.
- 기기 변경은 강사 화면에서 접속을 재발급하고 이전 기기를 막는다. 같은 기기라고 같은 학생으로 보지 않는다. 최종 종료 뒤 다음 사람에게 이전 가게나 기록을 잇지 않는다.
- 광장에 보이는 건 가게 이름, 전시 그림, 사진, 고른 소개 문구뿐이다. 개인 기록, 돌아보기, 학생 연결 정보는 별도 비공개로 둔다.
- 방문은 3교시 개장 직전 실제 참여자로 순환 배정한다(A→B→C→A). 요청이 오간 뒤엔 다시 섞지 않고, 강사나 예시가 대신하면 "대체 진행"으로 기록한다.
- 사진: 강사 화면에 자리 순서대로 가게 목록 → 찍으면 그 가게에 연결되고 다음으로 넘어간다. 건너뛰기, 다시 찍기, 사진 옮기기를 둔다. "촬영됨"과 "서버 저장 완료"를 구분하고 실패는 재시도 목록에 남긴다. 사진이 없으면 구상 그림으로 열고 "작품 사진 준비 중"으로 표시한다. 비공개 저장소, 짧은 링크 유효기간, 수업 종료 시 학생 접근 차단, 원본·썸네일·재촬영본·임시본까지 파기 확인.
- 광장 화면은 바뀐 가게와 요청 상태만 몇 초마다 갱신한다. 입력 중인 글이 지워지면 안 된다.
- "저장됨"은 서버가 확인했을 때만 표시한다. 단계 넘기기 버튼은 미완료 학생 수를 보여주고, 미완료를 완료로 바꾸지 않는다.
- AI 호출은 서버에서 한다. 보내는 건 손님 카드, 허용 재료, 학생 선택뿐이다(학생 번호, 사진, 자유 서술 속 개인 정보 제외). AI 장애 때는 준비된 예시로 진행하고, 예시를 쓴 것은 기록에서 구분한다.
- 그림: 광장 배경과 빈 가게 틀만 이미지로 쓰고, 간판 글자·버튼·상태는 화면 요소로 만든다. 이미지는 GPT로 만들 테니 필요한 그림 목록과 생성용 프롬프트를 문서로 같이 써줘.

[단계 - 각 단계가 끝나면 멈추고 보고한다. 다음 단계는 내가 요청할 때만]
0. 설계 문서(코드 없음)
1. 가장 위험한 연결 시험: 코드 입장 → 구상 저장 → 잠시 멈춤 → 재입장 → 강사 사진 연결
2. 조향사 전체 흐름: AI, 간판, 광장, 방문·요청·답장·반응, 돌아보기, 진로기록 저장, 교사용 슬라이드
3. 예외 처리와 리허설 준비: 기기 변경, 사진 실패, 결석 재배정, 중복 제출, AI·인터넷 장애, 리허설용 가짜 참여자 만들기
4. 실제 학생 기록 관문: 보관 기간과 파기 실행, 기록을 원하지 않는 학생의 진행 경로, 학교 제출용 처리 흐름 문서. 내 승인 전 운영 배포 금지
5. 시범 뒤: QR 진로 카드, 다른 프로그램 카드 추가
