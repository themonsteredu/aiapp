# 공예 공통 수업과 기존 활동 연결 — 2026-10-05

## 수업에서 쓰는 순서

광장은 모아랩의 공통 수업 공간이다. 기존 직업 앱은 수업 앞부분의 활동으로 연결한다.
학생은 모아랩 수업 코드로 한 번 입장하고 같은 자리에서 구상·제작 확인·교류·기록을 이어간다.

| 단계 | 학생 | 강사 |
|---|---|---|
| 입장 | 수업 코드와 내 자리 확인 | 수업 프로그램·담당 수업·자리 수 준비 |
| 기존 활동 또는 기본 구상 | 연결 앱을 열고 가져갈 영감 확인 | 앱이 없거나 열리지 않으면 공통 구상으로 안내 |
| 구상과 가게 | 손님·실제 키트 재료 확인, 구상 선택·수정, 이름·간판 저장 | 아직 구상을 저장하지 못한 자리 확인 |
| 제작 | 기기를 내려놓고 실물 제작 | 제작 전환·시연·제작 지도 |
| 개장 준비 | 실제 작품과 처음 구상 비교 | 자리별 작품 촬영 후 서버 저장 확인 |
| 광장 교류 | 친구 가게 방문·요청·답장·반응 | 실제 참여자 확인 후 개장 |
| 마무리 | 돌아보기·최종 기록 확인·저장 | 저장 여부 확인 후 종료 |

사회적 문제는 구상과 교류의 공통 기준이다. 조향사는 서로 다른 향 취향을 배려하는 작품과 설명을 생각한다.

## 이번 조향사 연결

조향사 수업 기본 설정 **v4**에는 `source_activity: {id: "ai-smell", version: 1}`이 들어 있다.
저장한 수업 설정과 이미 시작한 방은 수정하지 않는다. 새 설정을 저장해 새 수업에 준비해야 연결 화면이 나타난다.

강사: 모아랩 → 수업 프로그램 준비 → 진행할 수업에서 조향사 선택 → 기본 설정 불러오기 → 기존 활동 연결 확인 → 연결할 자료·설정 버전 확인 → 수업 설정 저장하기 → 담당 수업에 광장 준비 → 관리자의 시험 보관 기간 등록 → 학생에게 수업 코드 안내.

학생: 기존 활동 → **마음의 향기 타로 열기** → 활동 후 작품에 가져갈 분위기 선택·본인 확인 → **영감 저장하고 작품 구상으로 이어가기**.
분위기는 구상 화면에 남으며 최종 기록에도 같은 확인 출처로 이어진다. 다시 로그인하거나 영감을 다시 입력하지 않는다.
학생이 시향지와 실제 키트 재료를 확인하는 과정은 별도로 유지한다. 타로 결과로 배합·사용량·치료 효과를 결정하지 않는다.

기존 `ai-smell` 앱에는 결과 전송 기능이 없고 이번 작업에서도 그 저장소는 수정하지 않았다.
따라서 **앱 결과의 자동 수집이 아니라 학생이 확인한 영감을 연결**한다. 카드 리딩, 개인 질문·대화, 추천 향 전체를 가져오지 않는다.
앱을 못 쓰면 ‘기존 앱 없이 강사 안내로 골랐어요’를 선택한다. 최종 기록도 이 대체 진행을 구분한다.
외부 앱 화면을 닫거나 새로고침하면 앱 내부 진행은 초기화될 수 있지만 모아랩에 확인·저장한 영감은 유지된다.

## 다른 공예에 적용

기존 앱이 없으면 `source_activity`를 생략하고 공통 구상 화면부터 시작한다.
앱이 있으면 `lib/plaza-activity-source.js`에 검토한 연결 항목을 추가한다.
항목에는 고정 HTTPS 주소, 적용할 프로그램, 학생 확인 질문·선택지를 넣고 수업 설정에는 항목 번호와 버전만 둔다.
수업 설정에 임의 주소·스크립트·iframe 권한을 넣을 수 없다. 학생 번호·반 코드·접속 비밀값을 외부 URL에 넣지 않는다.
향후 자동 결과 전달을 추가한다면 원본 앱의 명시적 전송 기능과 수신 출처·내용 검증을 별도로 구현해야 한다.

## 저장과 접근 규칙

- 새 DB 표·자동 마이그레이션 없음. 기존 `plaza_drafts.content.source_activity`에 학생 확인 내용과 서버 시각을 저장한다.
- 영감 확인만으로 구상 완료나 가게 개장으로 집계하지 않는다. 완성 구상은 기존 간판 저장 이후에만 집계한다.
- 기존 수업·배정·기기 연결·보관 정책 검사를 통과해야 한다. 같은 저장 번호의 재시도는 한 번만 남는다.
- 구상 제안을 받은 뒤에는 앞의 영감을 바꾸지 않는다. 제작·최종 확정·수업 종료 이후 수정도 차단한다.
- 기존 AI 입력 범위는 유지한다. 영감 선택과 타로 해석·개인 질문은 외부 AI로 추가 전송하지 않는다.
- 진로기록의 `job-deck`, `job-class`, 서버 학생 식별과 원본 불변 규칙을 유지한다. 비기록 참여도 유지한다.
- 같은 출처에 업로드한 HTML의 격리 규칙은 변경하지 않는다. 래퍼는 검토된 별도 출처의 앱만 제한된 iframe으로 연다.

## 강사 촬영 화면

- 학생 입장 전에도 **카메라 켜기**로 미리보기를 확인할 수 있다. 사진 저장은 입장한 학생의 자리를 선택한 뒤 가능하다.
- 카메라 권한 허용과 실제 영상 재생을 모두 확인해야 **찍고 다음 자리**가 활성화된다. 영상이 멈추면 촬영도 잠긴다.
- 미리보기가 열리지 않으면 **기기 카메라로 촬영** 또는 **사진 앨범에서 선택**을 이용한다. 앱 안의 브라우저에서는 같은 수업을 Safari에서 열어 볼 수 있다.
- 학생 입장 대기, 사진 없이 참여, 수업 종료 상태를 촬영 버튼 옆에 표시한다. 사진 없이 참여한 학생의 사진은 두 대체 경로에서도 저장하지 않는다.
- 사진을 고르는 동안 선택한 자리가 바뀌어도 처음 선택한 대상에 연결한다. 촬영 허용이나 대상 연결이 바뀌면 저장을 막는다.
- 수업 종료·화면 이동·카메라 끄기 뒤에 늦게 도착한 권한 응답은 폐기하고 카메라를 해제한다.

영상 재생 처리는 [WebKit의 인라인 재생 안내](https://webkit.org/blog/6784/new-video-policies-for-ios/)와 [미디어 재생 완료 확인](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)을 참고했다. 실제 iPhone·iPad 카메라 권한과 촬영은 별도 확인이 필요하다.

## 검증 결과

### 2026-10-06 수업 준비 오류 안내

- 담당 수업이 없을 때 코드 미발급·만료·종료·미배정 가능성과 기본 유효 시간(2시간)을 표시한다. 코드 만들기·자료 관리 링크와 목록 새로고침을 제공한다.
- 수업 준비 API의 수업 만료, 자료 미배정, 학생 비공개·잠금 응답에 각각 `class_expired`, `deck_unassigned`, `deck_blocked` 코드를 붙였다. 서버의 거부 조건과 상태 코드는 그대로다.
- 이 세 가지 설정 오류는 작성한 폼을 지우지 않고 준비 버튼 옆에 실제 이유와 관리 링크를 보여준다. 서버가 확인하지 못한 저장은 같은 내용으로만 재시도한다.
- 실제 계정 권한 거절 때는 기존처럼 폼과 읽은 자료를 지운다. 서버의 구체적인 이유와 로그인 경로를 표시하고, 기능이 없는 주소(404)를 권한 오류로 표시하지 않는다.
- 구문 검사, 학생·프로그램 DOM 57개, 별도 가짜 DB의 수업 준비·완주 HTTP 검사 64개 통과. 권한 차단, 잠금·공개·배정 차단, 오류 뒤 폼 보존, 응답 유실 재시도, 최종 기록 보존을 확인했다.
- 신고된 실제 로그인 계정의 실패 원인은 스크린샷만으로 확정하지 않았다. 기존 화면이 숨기던 오류를 구분할 수 있게 한 수정이다. 시험 배포의 상태 API에서 DB 연결·스키마 준비는 확인했다.

| 확인 | 결과 |
|---|---|
| 구문·단위 회귀 | `npm run check`, `npm test` 185개 통과 |
| 기존 5단계 HTTP·DB 회귀 | 62개 통과, 다른 공예도 공통 흐름 완주 |
| 새 연결 HTTP·DB | 25개 통과. 확인·중복·권한·구상 보존·최종 기록·비기록·종료 확인 |
| 학생·강사 DOM | 390·768·1366 폭의 상태 동작 및 프로그램의 기존 활동 연결 선택 42개 통과 |
| 기존 학생 DOM | 14개 통과 |
| 강사 촬영 DOM | 53개 통과. 입장 전 미리보기, 영상 준비, 권한 오류, 기기 촬영·사진 선택, 자리 고정, 사진 거부, 종료 처리 모의 검증 |

DOM 시험은 실제 화면 배치·외부 앱 렌더링 검증이 아니다. 실제 iPad의 앱 화면·카메라·QR 인쇄와 실제 키트 수업은 확인 전이다.
시험에는 가짜 참여자·가짜 키트만 사용했고 실제 외부 AI 호출은 하지 않았다.
운영 배포·실제 학생 자료 수집 단계로 승격하지 않는다.
